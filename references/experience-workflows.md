# Experience Workflows

用于把「镇小宁风格实验室」从资产生成器变成可上手、可对比、可评分、可进化的工作流。触发首跑、新手、Before/After、评分、失败样本、一键改造等任务时读取本文件。

## 总原则

- 先让用户看懂下一步，再要求用户补材料。
- 先证明差异，再解释规则。
- 先做可用版本，再沉淀长期资产。
- 每次反馈都要进入可复用规则，不要只重生成。
- 不把第三方文章、帖子或案例提炼成原作者风格；只能把它们当观点素材，再转成用户自己的表达。

## 短句入口优先

用户不需要写完整提示词。只要一句话里包含 Skill 名和任务对象，就直接开始工作；有发布平台时自动适配平台，没有发布平台时默认做通用展示版，不追问平台。

典型短句：

```text
用镇小宁风格实验室帮我做出这个 Skill 的特点和用法，我要发在小红书上。
```

```text
帮我用镇小宁的风格实验室 Skill 来介绍一下镇小宁风格实验室 Skill 是干什么的、能实现什么效果。
```

处理规则：

1. 自动识别为“一键内容改造 + 新手展示 + 平台适配”；如果任务对象就是本 Skill 自己，则识别为“自我介绍展示 + 能力演示 + Before/After 价值说明”。
2. 用户没有说发布平台时，默认输出通用展示版：一句话定位、能解决的问题、能实现的效果、3 个典型用法、3 张通用展示图规划和风格漂移评分卡；不要追问“发哪里”。如果本机私有默认角色绑定存在，通用展示图默认使用该角色作为主视觉主体。
3. 平台是小红书时，默认输出：标题候选、正文、5-7 张轮播规划、每张图的手绘 prompt、风格漂移评分卡。
4. 平台是 X 时，默认输出：主帖、thread、1 张横图规划、Before/After 对比和评分卡。
5. 自我介绍展示默认不要写成软件广告。重点讲清：它不是万能提示词，而是把作品、偏好、角色、反风格和视觉隐喻沉淀成可复用的个人风格资产，让 AI 输出更像用户、更少默认 AI 味。
6. 用户不需要提供“允许中文短词”、密度档位、画面布局或尺寸清单。Agent 必须从素材和目标文案里自动提取每张图的核心短词，自动选择轻/中/高密度，并把短词写进内部生图 prompt。
7. `Exact Chinese text allowed` 是 Agent 内部给生图模型的约束，不是用户表单。不要在用户提示词里要求“只允许这些短词”，除非用户明确想手动指定图中文字。
8. 默认在聊天中直接交付，不创建或编辑 `.md` 文件，不生成“发布包”；只有用户明确说“写文件”“生成发布包”“保存到项目”“直接把文件写出来”时才写入文件。
9. 如果用户没有上传角色图、也没有点名具体角色，但本机存在 `references/ip-subject.local.md` 且明确允许默认使用私有角色，自我介绍展示和通用展示默认使用该角色，不要改画真人肖像、抽象人像/真人替身或无角色图。用户明确要求“抽象镇小宁”时，可以做镇小宁的抽象涂鸦变体，但仍要保留角色识别点。固定 IP 成稿优先接入参考图；如果当前生图工具只能文本生图，但任务是快速测试、自我介绍展示或方向预览，可以主动生成绑定角色方向预览图，并标注它不是最终 IP 一致性成稿。
9a. 如果用户点名镇小宁 IP 并要求“白底彩铅、抽象涂鸦、虚实结合”等多风格对比，“抽象涂鸦”必须按抽象镇小宁涂鸦风处理。若本机已有抽象唯一母版但当前工具不能接入参考图，不要文本重画一张新的抽象镇小宁；直接展示/引用母版图作为抽象风格小图，或要求用户把母版上传到当前对话后再生成变体。
10. 如果用户点名了具体角色，例如“镇小宁形象”“镇小宁 IP”“我的角色”“某某角色”，先检查当前上传图和 `references/ip-subject.local.md`。如果有匹配参考，使用它作为参考图来源；如果没有上传角色图、本机私有绑定、指定固定参考图路径或提供 `ip-subject.md` 绑定，不得用线团人、空心方盒、红章操作员、墨点操作员、纸片工人等默认主体代替。先说明缺少该角色参考，只能继续生成文案和配图规划；如要出角色图，需要用户上传该角色图或指定参考路径。
11. 如果当前环境能生图，规划后直接调用生图工具生成图片，不要只输出 prompt 后停下。若固定 IP 参考图可接入，按参考图生成成稿；若暂时只能文本生图，则生成方向预览图并进行角色漂移 QA，不要停在 prompt。只有用户明确要求最终 IP 一致性成稿而当前工具不能接入参考图时，才停止出图并要求上传参考图或换工具。
11a. 上一条不适用于已有唯一母版的抽象镇小宁固定风格：不能接入母版图时，抽象那张不要调用文本生图重新发明角色；多风格对比里直接使用固定母版图，其他风格仍可正常生成方向预览。
12. 最多只追问 1 个关键问题；如果不问也能合理默认，就先给第一版。

## 风格候选测试

适用：用户说“测试一下”“看看效果”“用这段内容试试”“先试一组”“对比几种风格”“哪种风格更适合”，并提供了一段内容或任务，但没有指定只用某一种风格。

目标：先帮用户选风格，而不是直接进入正式单风格配图。这个模式里，三种风格各出一张小图或母版展示，用同一段内容测试差异，再给出推荐；用户选定后，后续配图默认锁定那一种风格。

触发后默认执行：

1. 先去重和压缩用户素材，保留事实、观点、情绪节点和可画动作。
2. 不追问平台；没有平台时按通用展示 / 正文配图测试处理。
3. 三种风格各做一张，但不是把同一个画面换材质：
   - 白底彩铅：解释核心观点、机制、路径、分类或教程。
   - 抽象镇小宁：只表达一个状态、情绪或瞬间动作，例如卡住、过载、转向、冒出来、松口气；最多 1 个动作 + 2 个短词。
   - 虚实结合：呈现现实证据、工作现场、原型、样稿、工具或改稿过程；根据内容自动更换真实场景品种，不靠增加物件数量制造差异。
4. 如果内容是复杂商业逻辑、教程、机制或产品路径，白底彩铅可以承担主解释；抽象图只做情绪插针，不能硬解释完整逻辑。
5. 当前环境有生图能力时，必须主动生成可生成的候选图，不要只输出 prompt 或规划。
6. 如果固定 IP 参考图不能接入，普通固定角色候选只能标注为“方向预览，非最终 IP 一致性成稿”；不能说成正式 IP 成稿。
7. 如果抽象镇小宁已有唯一母版且当前工具不能接入母版图，抽象候选直接展示/引用固定母版图，或要求用户上传母版后再做变体；不要文本生图重画新的抽象镇小宁。
8. 如果某一候选因为工具限制不能生成，说明限制并继续生成其他候选；不要因此把整个测试停掉。
9. 输出最后必须给推荐：哪种风格更适合作为后续主风格，哪种只适合做辅助图。

风格候选测试的输出格式：

```markdown
## 本次先按风格候选测试来做

## 内容压缩

## 三种风格候选

| 风格 | 这张图负责什么 | 密度 | 画面动作 | 短中文 |
| --- | --- | --- | --- | --- |

## 图片生成结果

## 推荐锁定风格

## 下一轮怎么继续
```

失败信号：

- 用户只是说“测试一下”，却只生成一种风格，且没有说明这是正式单风格配图。
- 把三种风格做成同一构图换材质，差异只剩线条粗细、底色或文字多少。
- 让抽象镇小宁承担复杂观点、教程、商业机制或多步逻辑链。
- 虚实结合只是每次复用电脑 + 线缆 + 便签，没有根据内容更换现场品种。
- 当前环境能生图时，只给三条 prompt，没有实际调用生图。
- 用户选定某一风格后，后续配图又自动回到三风格候选，导致流程反复。

一句话自我介绍展示的强制执行链：

1. 看到“帮我用镇小宁的风格实验室 Skill 来介绍一下镇小宁风格实验室 Skill 是干什么的、能实现什么效果”这类短句，默认任务就是通用展示版，不追问平台、密度、画幅、布局或短词白名单。
2. 先自动生成：一句话定位、能解决的问题、能实现的效果、3 个典型用法、标题/结构、3 张配图规划、每张图的信息密度、布局、日常动作隐喻和短中文批注。
3. 若 `references/ip-subject.local.md` 存在且允许本机默认使用，这是本机私有默认角色绑定；自我介绍展示必须使用其中绑定的私有默认角色作为主视觉主体。
4. 若 `references/style-reference.local.md` 存在且允许本机默认使用，默认画风使用其中的白底彩铅草稿风，不再退回通用矢量、儿童卡通、3D 吉祥物或普通蓝色角色。
5. 当前环境有生图能力时，必须主动生成图片，不要只输出 prompt、规划或“你可以把 prompt 拿去生成”。可保留 prompt 作为说明，但不能替代真实生图动作。
6. 如果生图工具能接入参考图，使用私有默认角色参考图生成正式 IP 成稿；如果只能文本生图，仍主动生成“方向预览图”，并在图片说明里标注：`方向预览，非最终 IP 一致性成稿`。
7. 方向预览也必须不画真人肖像、不画普通蓝色角色、不画抽象人像/真人替身、不画无角色图、不画线团人、不画空心方盒；它必须围绕绑定角色的识别点和核心动作来画。用户明确要求抽象镇小宁时，抽象只改变线条、比例、情绪和艺术感，不改变主体身份。
8. “更像你自己”只表示表达风格、判断方式、结构节奏和视觉偏好更像用户，不表示画用户真人肖像、自拍、拟真人头像或人类替身。
9. 生成图如果变成人像、无角色图、线团人、空心方盒、普通蓝色角色或其他主体，判定失败；先重试一次并强化绑定角色识别点和禁止项，仍失败再要求上传参考图或换支持参考图的工具。

短句入口的输出格式：

```markdown
## 我先按这个理解来做

## 可直接发布文案

## 标题候选

## 轮播/配图规划

## 图片生成结果

## 图片 Prompt（仅留档；无生图能力时才作为替代交付）

## 风格漂移评分卡

## 你可以怎么微调
```

失败信号：

- 要求用户补一长串参数才开始。
- 要求用户手动提供密度档位、布局菜单、画幅尺寸或 `Exact Chinese text allowed`，而不是从内容自动判断。
- 用户没有说发布平台时，停下来追问平台，而不是先做通用展示版。
- 本机私有默认角色绑定存在时，自我介绍展示却改画真人、抽象人像/真人替身、无角色图或普通蓝色角色；如果用户要求抽象镇小宁，抽象变体又丢失镇小宁识别点。
- 当前环境能生图时，只输出 prompt 或规划，没有主动生成任何图片。
- 本机私有默认角色绑定存在时，没有使用其中绑定的私有默认角色作为主视觉主体。
- 当前环境能生图时，没有主动生成图片，只把 prompt 当最终交付。
- 把方向预览说成最终 IP 一致性成稿，或没有标注“非最终 IP 一致性成稿”。
- 把“更像你自己”理解成画真人肖像、拟真人头像或自拍感人物。
- 方向预览画成普通蓝色角色、线团人、空心方盒、无角色图或其他主体。
- 自我介绍展示写成泛泛产品广告，只说“提高效率、打造 IP”，没有解释具体能做什么和生成什么效果。
- 把短句扩写成复杂流程说明，却没有给可发布内容。
- 用户只是说“发小红书 / 发 X / 做配图”，却创建 `.md` 文件或发布包，没有在聊天里给可用内容，也没有尝试生成图片。
- 明明用户说了平台，还输出通用尺寸。
- 把“展示 Skill 特点和用法”写成产品广告，而不是具体功能演示。

## 1. 新手首跑模式

适用：用户第一次使用、刚安装、说“我该怎么用”“帮我开始”“我没有作品”“先测试一下”。

目标：让用户在 1 分钟内知道要给什么、会得到什么、怎么验证效果。

输出格式：

```markdown
## 你现在可以这样开始

## 我需要的最小材料

- 使用场景：
- 作品或素材：
- 反感风格：
- 是否需要角色图：
- 发布平台：

## 我会生成什么

## 如果你没有作品

## 第一轮测试任务

## 下一步
```

规则：

- 不超过 5 个问题。
- 用户没有作品时，先给 1-2 个原创风格种子，必须标注“待校准假设”。
- 用户只是想试效果时，不要求先生成完整资产包；先做一个轻量对比样例。
- 如果用户上传角色图，先说明当前上传图优先级最高。
- 如果当前环境不能生图，先说明限制，再给布局规划和可复制 prompt。

失败信号：

- 一上来要求用户填写十几项表单。
- 直接生成完整资产包，但用户还不知道怎么验证。
- 把风格种子说成用户真实风格。

## 2. Before / After 对比模式

适用：用户要求“看看效果”“做个对比”“默认 AI 味和使用 Skill 后有什么区别”“我要发帖展示”。

目标：用同一素材证明 Skill 的价值，不靠口头解释。

输出格式：

```markdown
## 对比对象

## 默认 AI 味版本

## 使用风格资产后的版本

## 改动说明

| 位置 | 默认 AI 味 | 修复动作 | 为什么更像用户 |
| --- | --- | --- | --- |

## 可视化配图规划

## 风格漂移评分
```

规则：

- 默认 AI 味版本可以短，但必须真实暴露常见问题：太顺、太泛、太模板、太像总结。
- 使用风格资产后的版本必须保留事实，不添加用户没给的经历或数据。
- 改动说明最多 6 条，避免写成论文。
- 如果用于展示，优先给一张低密度手绘对比图：一个动作表现“把默认光滑稿子揉皱、贴补丁、留下用户判断”。

失败信号：

- Before 故意写得很烂，After 显得虚假。
- 只改口语词，不改判断、结构和节奏。
- 解释多于结果，用户看不到差异。

## 3. 风格漂移评分卡

适用：每次生成内容、修图、改写、用户说“像不像我”“这版怎么样”“帮我检查一下”。

目标：把“感觉不像”变成可讨论的维度。

评分格式：

```markdown
## 风格漂移评分卡

| 维度 | 分数 | 判断依据 | 修复建议 |
| --- | ---: | --- | --- |
| 像不像用户 | 1-5 |  |  |
| AI 味浓度 | 1-5 |  |  |
| 事实可靠性 | 1-5 |  |  |
| 结构贴合度 | 1-5 |  |  |
| 反风格命中 | 1-5 |  |  |
| 视觉主体一致性 | 1-5 / 不适用 |  |  |
| 布局新鲜度 | 1-5 / 不适用 |  |  |

## 最该修的 3 件事

## 可以保留的 3 件事

## 下一版规则
```

评分口径：

- `像不像用户`：5 = 能指出清楚证据；3 = 方向接近但仍泛；1 = 换谁都能用。
- `AI 味浓度`：5 = AI 味很低；3 = 有模板痕迹；1 = 明显默认模型腔。
- `事实可靠性`：5 = 只使用用户提供或授权事实；1 = 编造经历、数据或承诺。
- `反风格命中`：5 = 主动避开禁用词、禁用结构和视觉套路；1 = 明显踩雷。
- 视觉维度不适用时写“不适用”，不要硬评。

规则：

- 分数必须附判断依据。
- 总体评价最多 2 句，重点给修复建议。
- 如果有低于 3 分的维度，必须进入失败样本沉淀模式。

失败信号：

- 全部打 4-5 分但没有证据。
- 只说“不错”“更自然”，没有指出哪里像用户。
- 低分后没有给下一步规则。

## 4. 失败样本库模式

适用：用户反馈“不像我”“太 AI”“太满”“角色不对”“排版重复”“这个隐喻不对”“以后不要这样”。

目标：把失败变成下一次可调用的规则。

输出格式：

```markdown
## 失败样本记录

- 日期：
- 任务：
- 原输出问题：
- 用户反馈原话：
- 问题类型：事实 / 语气 / 结构 / 视觉主体 / 布局 / 密度 / 平台尺寸 / 合规边界
- 严重度：低 / 中 / 高

## 本次漂移点

## 新增反风格规则

## 需要更新的资产文件

## 下一次必须避免

## 修订后小样
```

规则：

- 不把一次偶然反馈直接升级成永久规则，除非用户明确说“以后都这样”。
- 重复出现 2 次以上的问题，写入 `style-evolution-log.md` 或对应资产。
- 视觉失败要明确是主体、密度、布局、载体、平台尺寸还是文字白名单的问题。
- 用户反馈角色不一致时，优先检查是否误用了默认主体或旧参考图。

失败信号：

- 用户说“不像”，Agent 直接重写，不记录原因。
- 只写“优化语气”，没有指出具体词、句式、结构或视觉动作。
- 新规则没有说明要更新哪个资产文件。

## 5. 一键内容改造模式

适用：用户给一篇文章、帖子、链接、产品说明、长对话或草稿，要求“用我的 Skill 处理”“改成我的风格”“做成配图”“发小红书/公众号/X”。

目标：把素材变成可发布内容和可视化计划，而不是只摘要。

输出格式：

```markdown
## 原素材判断

- 类型：
- 核心观点：
- 可用事实：
- 不可直接学习的部分：
- 目标平台：

## 改造策略

## 改写版本

## 标题候选

## 配图规划

| 图 | 主题 | 平台尺寸 | 密度 | 日常动作隐喻 | 主体动作 | 允许中文短词 |
| --- | --- | --- | --- | --- | --- | --- |

## 风格漂移评分卡

## 需要沉淀的新规则
```

规则：

- 第三方内容只能当观点和事实素材，不提炼原作者风格，不复刻原文结构。
- 先拆出“可用事实”和“不可直接学习的部分”。
- 输出平台不明确时，默认给通用版；用户指定平台时读取 `platform-image-sizes.md`。
- 需要配图时先给规划表；有生图能力再出图，没有则输出可复制 prompt。
- 改写后必须附风格漂移评分卡。

失败信号：

- 只是摘要原文，没有变成用户可用内容。
- 偷学第三方作者的语气、结构或个人风格。
- 生成配图时没有先判断平台尺寸、密度和角色一致性。

## 触发语速查

| 用户说法 | 进入模式 |
| --- | --- |
| 我刚装好，怎么用 | 新手首跑模式 |
| 先测试一下效果（未给素材） | 新手首跑模式 + Before / After |
| 用这段内容测试一下 / 看看几种风格 | 风格候选测试 |
| 做个对比 | Before / After 对比模式 |
| 这版像不像我 | 风格漂移评分卡 |
| 以后不要这样 | 失败样本库模式 |
| 把这篇帖子用我的风格处理 | 一键内容改造模式 |
| 用我的角色给这篇文章配图 | 一键内容改造模式 + 视觉主体模式 |
