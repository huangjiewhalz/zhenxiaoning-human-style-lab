# Experience Workflows

用于把「镇小宁风格实验室」从资产生成器变成可上手、可对比、可评分、可进化的工作流。触发首跑、新手、Before/After、评分、失败样本、一键改造等任务时读取本文件。

## 总原则

- 先让用户看懂下一步，再要求用户补材料。
- 先证明差异，再解释规则。
- 先做可用版本，再沉淀长期资产。
- 每次反馈都要进入可复用规则，不要只重生成。
- 不把第三方文章、帖子或案例提炼成原作者风格；只能把它们当观点素材，再转成用户自己的表达。

## 短句入口优先

用户不需要写完整提示词。只要一句话里包含 Skill 名、任务对象和发布平台，就直接开始工作。

典型短句：

```text
用镇小宁风格实验室帮我做出这个 Skill 的特点和用法，我要发在小红书上。
```

处理规则：

1. 自动识别为“一键内容改造 + 新手展示 + 平台适配”。
2. 平台是小红书时，默认输出：标题候选、正文、5-7 张轮播规划、每张图的手绘 prompt、风格漂移评分卡。
3. 平台是 X 时，默认输出：主帖、thread、1 张横图规划、Before/After 对比和评分卡。
4. 默认在聊天中直接交付，不创建或编辑 `.md` 文件，不生成“发布包”；只有用户明确说“写文件”“生成发布包”“保存到项目”“直接把文件写出来”时才写入文件。
5. 如果用户没有上传角色图、也没有点名具体角色，但本机存在 `references/ip-subject.local.md` 且明确允许默认使用私有角色，可以直接使用该角色；否则可以先使用原创抽象主体或无主体手绘隐喻，并标注“可替换为用户角色”。
6. 如果用户点名了具体角色，例如“镇小宁形象”“镇小宁 IP”“我的角色”“某某角色”，先检查当前上传图和 `references/ip-subject.local.md`。如果有匹配参考，直接使用它；如果没有上传角色图、本机私有绑定、指定固定参考图路径或提供 `ip-subject.md` 绑定，不得用线团人、空心方盒、红章操作员、墨点操作员、纸片工人等默认主体代替。先说明缺少该角色参考，只能继续生成文案和配图规划；如要出角色图，需要用户上传该角色图或指定参考路径。
7. 如果当前环境能生图，规划后直接调用生图工具生成图片，不要只输出 prompt 后停下；不能生图时，明确说明限制并输出可复制 prompt。
8. 最多只追问 1 个关键问题；如果不问也能合理默认，就先给第一版。

短句入口的输出格式：

```markdown
## 我先按这个理解来做

## 可直接发布文案

## 标题候选

## 轮播/配图规划

## 图片 Prompt

## 风格漂移评分卡

## 你可以怎么微调
```

失败信号：

- 要求用户补一长串参数才开始。
- 把短句扩写成复杂流程说明，却没有给可发布内容。
- 用户只是说“发小红书 / 发 X / 做配图”，却创建 `.md` 文件或发布包，没有在聊天里给可用内容，也没有尝试生成图片。
- 明明用户说了平台，还输出通用尺寸。
- 把“展示 Skill 特点和用法”写成产品广告，而不是具体功能演示。

## 1. 新手首跑模式

适用：用户第一次使用、刚安装、说“我该怎么用”“帮我开始”“我没有作品”“先测试一下”。

目标：让用户在 1 分钟内知道要给什么、会得到什么、怎么验证效果。

输出格式：

```markdown
## 你现在可以这样开始

## 我需要的最小材料

- 使用场景：
- 作品或素材：
- 反感风格：
- 是否需要角色图：
- 发布平台：

## 我会生成什么

## 如果你没有作品

## 第一轮测试任务

## 下一步
```

规则：

- 不超过 5 个问题。
- 用户没有作品时，先给 1-2 个原创风格种子，必须标注“待校准假设”。
- 用户只是想试效果时，不要求先生成完整资产包；先做一个轻量对比样例。
- 如果用户上传角色图，先说明当前上传图优先级最高。
- 如果当前环境不能生图，先说明限制，再给布局规划和可复制 prompt。

失败信号：

- 一上来要求用户填写十几项表单。
- 直接生成完整资产包，但用户还不知道怎么验证。
- 把风格种子说成用户真实风格。

## 2. Before / After 对比模式

适用：用户要求“看看效果”“做个对比”“默认 AI 味和使用 Skill 后有什么区别”“我要发帖展示”。

目标：用同一素材证明 Skill 的价值，不靠口头解释。

输出格式：

```markdown
## 对比对象

## 默认 AI 味版本

## 使用风格资产后的版本

## 改动说明

| 位置 | 默认 AI 味 | 修复动作 | 为什么更像用户 |
| --- | --- | --- | --- |

## 可视化配图规划

## 风格漂移评分
```

规则：

- 默认 AI 味版本可以短，但必须真实暴露常见问题：太顺、太泛、太模板、太像总结。
- 使用风格资产后的版本必须保留事实，不添加用户没给的经历或数据。
- 改动说明最多 6 条，避免写成论文。
- 如果用于展示，优先给一张低密度手绘对比图：一个动作表现“把默认光滑稿子揉皱、贴补丁、留下用户判断”。

失败信号：

- Before 故意写得很烂，After 显得虚假。
- 只改口语词，不改判断、结构和节奏。
- 解释多于结果，用户看不到差异。

## 3. 风格漂移评分卡

适用：每次生成内容、修图、改写、用户说“像不像我”“这版怎么样”“帮我检查一下”。

目标：把“感觉不像”变成可讨论的维度。

评分格式：

```markdown
## 风格漂移评分卡

| 维度 | 分数 | 判断依据 | 修复建议 |
| --- | ---: | --- | --- |
| 像不像用户 | 1-5 |  |  |
| AI 味浓度 | 1-5 |  |  |
| 事实可靠性 | 1-5 |  |  |
| 结构贴合度 | 1-5 |  |  |
| 反风格命中 | 1-5 |  |  |
| 视觉主体一致性 | 1-5 / 不适用 |  |  |
| 布局新鲜度 | 1-5 / 不适用 |  |  |

## 最该修的 3 件事

## 可以保留的 3 件事

## 下一版规则
```

评分口径：

- `像不像用户`：5 = 能指出清楚证据；3 = 方向接近但仍泛；1 = 换谁都能用。
- `AI 味浓度`：5 = AI 味很低；3 = 有模板痕迹；1 = 明显默认模型腔。
- `事实可靠性`：5 = 只使用用户提供或授权事实；1 = 编造经历、数据或承诺。
- `反风格命中`：5 = 主动避开禁用词、禁用结构和视觉套路；1 = 明显踩雷。
- 视觉维度不适用时写“不适用”，不要硬评。

规则：

- 分数必须附判断依据。
- 总体评价最多 2 句，重点给修复建议。
- 如果有低于 3 分的维度，必须进入失败样本沉淀模式。

失败信号：

- 全部打 4-5 分但没有证据。
- 只说“不错”“更自然”，没有指出哪里像用户。
- 低分后没有给下一步规则。

## 4. 失败样本库模式

适用：用户反馈“不像我”“太 AI”“太满”“角色不对”“排版重复”“这个隐喻不对”“以后不要这样”。

目标：把失败变成下一次可调用的规则。

输出格式：

```markdown
## 失败样本记录

- 日期：
- 任务：
- 原输出问题：
- 用户反馈原话：
- 问题类型：事实 / 语气 / 结构 / 视觉主体 / 布局 / 密度 / 平台尺寸 / 合规边界
- 严重度：低 / 中 / 高

## 本次漂移点

## 新增反风格规则

## 需要更新的资产文件

## 下一次必须避免

## 修订后小样
```

规则：

- 不把一次偶然反馈直接升级成永久规则，除非用户明确说“以后都这样”。
- 重复出现 2 次以上的问题，写入 `style-evolution-log.md` 或对应资产。
- 视觉失败要明确是主体、密度、布局、载体、平台尺寸还是文字白名单的问题。
- 用户反馈角色不一致时，优先检查是否误用了默认主体或旧参考图。

失败信号：

- 用户说“不像”，Agent 直接重写，不记录原因。
- 只写“优化语气”，没有指出具体词、句式、结构或视觉动作。
- 新规则没有说明要更新哪个资产文件。

## 5. 一键内容改造模式

适用：用户给一篇文章、帖子、链接、产品说明、长对话或草稿，要求“用我的 Skill 处理”“改成我的风格”“做成配图”“发小红书/公众号/X”。

目标：把素材变成可发布内容和可视化计划，而不是只摘要。

输出格式：

```markdown
## 原素材判断

- 类型：
- 核心观点：
- 可用事实：
- 不可直接学习的部分：
- 目标平台：

## 改造策略

## 改写版本

## 标题候选

## 配图规划

| 图 | 主题 | 平台尺寸 | 密度 | 日常动作隐喻 | 主体动作 | 允许中文短词 |
| --- | --- | --- | --- | --- | --- | --- |

## 风格漂移评分卡

## 需要沉淀的新规则
```

规则：

- 第三方内容只能当观点和事实素材，不提炼原作者风格，不复刻原文结构。
- 先拆出“可用事实”和“不可直接学习的部分”。
- 输出平台不明确时，默认给通用版；用户指定平台时读取 `platform-image-sizes.md`。
- 需要配图时先给规划表；有生图能力再出图，没有则输出可复制 prompt。
- 改写后必须附风格漂移评分卡。

失败信号：

- 只是摘要原文，没有变成用户可用内容。
- 偷学第三方作者的语气、结构或个人风格。
- 生成配图时没有先判断平台尺寸、密度和角色一致性。

## 触发语速查

| 用户说法 | 进入模式 |
| --- | --- |
| 我刚装好，怎么用 | 新手首跑模式 |
| 先测试一下效果 | 新手首跑模式 + Before / After |
| 做个对比 | Before / After 对比模式 |
| 这版像不像我 | 风格漂移评分卡 |
| 以后不要这样 | 失败样本库模式 |
| 把这篇帖子用我的风格处理 | 一键内容改造模式 |
| 用我的角色给这篇文章配图 | 一键内容改造模式 + 视觉主体模式 |
