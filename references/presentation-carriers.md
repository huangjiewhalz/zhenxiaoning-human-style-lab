# Presentation Carriers

用于避免视觉输出总是回到纸、笔、卡片和文件夹。先根据内容选择“日常动作隐喻”，再选择动作发生的呈现载体、布局和密度。

呈现载体不是画风，也不是第一决策。画风可以仍然是铅笔、蜡笔、红笔或手绘线稿；真正决定画面是否有味道的是：角色在一个普通生活动作里如何遮挡、翻找、露出、压住、撕开、抖落、修补或沉淀信息。

## 选择原则

1. 先看内容关系：找、藏、掀、夹、压、揉、撕、抖、晾、缝、补、擦、称、泡、沉、捞。
2. 再选动作发生的载体家族，不要默认选纸面文具。
3. 同一系列里，相邻两张不能使用同一载体家族。
4. 纸张、卡片、便签、文件夹只是一类基础载体；连续 3 张以内最多用 1-2 张。
5. 如果用户上传了真实截图、网页、产品或角色，只抽象成局部物件，不临摹完整界面或官方标志。
6. 轻配图优先使用动作局部，不画完整场景；新颖载体不能变成“大背景 + 纸片信息”。
7. 每次选择载体时，必须同时写出“日常动作隐喻”和“视觉隐喻动作”：这个画面里谁在翻找、遮挡、露出、夹住、压住、撕开、抖落或补回什么。不要只写场景名。
8. 低密度图必须先选“日常动作隐喻”，再选可用道具；允许 2-4 个物件，但必须围绕一个动作关系。
9. 如果必须使用场景，场景要粗糙、手作、不精致，像草稿本里的小剧场，不像完成度很高的商业插画。

## 视觉隐喻规则

好的载体不是装饰，也不是把抽象词写到道具上，而是用一个日常动作让读者直觉感到“哦，它是在表达这个意思”。

- 先判断内容关系，再选生活动作：找、藏、掀、夹、压、揉、撕、抖、晾、缝、补、擦、称、泡、沉、捞。
- 隐喻必须能被画出来，而不是只适合写出来。比如“找信息”不要画搜索框，优先画从被子下面摸出皱纸条、从卡纸下面掀开线索、从抽屉缝里夹出小标签。
- 轻配图只画一个动作关系，但不等于只画一个物件：可以有 2-4 个物件形成遮挡、露出、压住、夹住或处理关系。
- 不要堆多个隐喻。一个画面里同时出现剪辑台、显影盘、棋盘和温室，会变成谜语。
- 不要使用需要文化背景才能看懂的隐喻；优先日常、低科技、手工、真实材料。
- 不要把隐喻解释写进画面。图里只允许短词，隐喻靠物件、动作、空间关系成立。
- 如果隐喻需要解释超过 3 秒才懂，换成更直接的动作。

## 日常动作隐喻表

第一决策是“这件事像生活里的哪个动作”，不是“信息应该放在哪种载体里”。载体和道具只能服务动作关系。

| 动作 | 适合表达 | 画面做法 | 避免 |
| --- | --- | --- | --- |
| 找 | 找信息、找证据、找灵感 | 从被子下面摸出皱纸条；从卡纸下面掀出线索；从抽屉缝里夹出标签 | 搜索框、放大镜图标、资料墙 |
| 藏 | 暂存、未公开、暗线 | 小纸条压在杯底；线索夹在书页里；答案露出一角 | 保险箱、锁头图标 |
| 掀 | 发现、揭开真相、看见结构 | 掀开被角、桌布角、卡纸角，下面露出少量关键痕迹 | 大幕布揭幕式海报 |
| 夹 | 保留、标记、关联 | 纸条夹在书页、票根夹在本子、便签夹在旧相框边 | 一排卡片夹子 |
| 压 | 约束、优先级、被盖住的问题 | 卡纸压住杂音；杯子压住待办；书压住跑偏稿 | 重物压大标题 |
| 揉 | 去 AI 味、去光滑、重新处理 | 太光滑的稿纸被揉皱后摊开；边角有手写补丁 | 故意做脏、做破、低质量 |
| 撕 | 拆开、去包装、去模板 | 从塑料包装里撕出一张有手痕的稿；撕掉模板外壳 | 暴力撕裂海报感 |
| 抖 | 筛需求、清杂质、留下重点 | 抖旧桌布，杂物落下，只剩几颗有用东西 | 直白筛子图标 |
| 晾 | 沉淀、等待、慢慢成型 | 小纸条晾在绳上；湿稿纸晾干后字迹显出 | 精致洗衣房场景 |
| 缝 | 修补、连接、风格统一 | 两段内容用粗线缝在一起；边角针脚不齐 | 时装大片、完整裁缝间 |
| 补 | 版本迭代、修复跑偏 | 胶带补住红点；手写补丁贴回稿纸边 | 机械维修工厂 |
| 擦 | 去噪、去模板、清理 | 橡皮擦掉套话，只剩浅浅笔迹 | 清洁用品广告 |
| 称 | 权衡、取舍、优先级 | 小秤一边是杂音，一边是真需求 | 法庭天平、宏大审判 |
| 泡 | 消化、吸收、口吻变软 | 纸条泡进杯子，生硬词慢慢散开 | 精致咖啡广告 |
| 沉 | 长期沉淀、内容发酵 | 小纸片沉到杯底，水面只剩安静痕迹 | 发酵瓶老套表达 |
| 捞 | 从混乱里取出有用物 | 用小勺从杯底捞出答案；从纸堆缝里捞出线索 | 打捞深海宏大隐喻 |
| 拼回去 | 重组、结构修复 | 几块揉皱纸片被拼回一张不完美但可读的稿 | 标准拼图模板 |
| 贴住 | 控制噪声、停止打扰 | 胶带贴住吵闹红点，旁边露出真正有用的纸条 | 平台 UI 通知墙 |

## 隐喻动作库

先选“内容关系”，再选“画面动作”。载体只是动作发生的地方。

| 内容关系 | 画面动作 | 可选隐喻 | 避免 |
| --- | --- | --- | --- |
| 分隔信息 | 切开、分盘、分格、分层 | 餐盘分格、便当盒、刀叉分切、裁缝纸样、印刷拼版、抽屉分格 | 三张卡片横排、只写“分类” |
| 信息筛选 | 过筛、滤出、调频、挑拣 | 筛面粉、漏勺滤水、收音调频、邮局分拣、索引抽屉 | 打捞式深度隐喻、密集搜索 UI |
| 信息优先级 | 主菜在中间、配菜靠边、聚光、前后景 | 晚餐摆盘、影棚打光、小店货架前排、舞台聚光 | 大标题压住画面 |
| 合并重组 | 拼盘、和面、缝合、拼版、接线 | 拼盘组合、揉面成团、裁缝缝合、老式总机接线、拼图/积木 | 复杂机械流程 |
| 前后对比 | 生熟、粗细、清浊、模糊清晰 | 生料到成品、陶坯到修坯、镜片对焦、暗房显影 | 左右两栏 PPT 对比 |

可以使用餐桌、刀叉、切分、摆盘等生活隐喻；不要把某个已被公开案例识别的鱼形切分画面当默认模板。如果用户明确要求鱼、肉、餐桌等物件，可以使用，但必须改变材料来源、视角、动作和信息承载方式。

## 隐喻方式

根据画面用途自动选择隐喻方式，不让用户先选菜单。

| 隐喻方式 | 默认用途 | 画面要求 | 避免 |
| --- | --- | --- | --- |
| 秒懂型 | 教程、功能说明、平台尺寸、用户明确要讲清楚 | 物件关系直接，动作明确，例如分格盘、筛子、打样纸、安全区框 | 过度氛围化，看不出信息关系 |
| 延迟型 | 正文配图、个人 IP、观点、社媒内容、用户想要有味道 | 第一眼是孤独、有留白、粗糙的小物件或小场景，第二眼读出关系 | 只剩氛围，没有动作或内容线索 |
| 系统型 | 方法论、复盘、课程讲义、无限画布、一张图讲清楚 | 可以有工作台或多区块，但必须手绘粗糙、有主路径 | 商业信息图、PPT 架构图、精修 UI |

默认分流：

- 低密度正文配图：延迟型优先，只画一个小局部里的动作关系，可有 2-4 个物件，但不画完整场景。
- 中密度解释图：秒懂型优先，允许粗糙小场景，但不画完整复杂空间。
- 高密度工作台：系统型优先，可以扩大场景，但仍要粗糙、不精修。

## 粗糙场景规则

粗糙不是低质量，而是保留手绘、不完美和人味。

- 允许线条歪、透视不准、边缘不整齐、物件比例略笨拙。
- 场景像创作者草稿本里的小剧场：一角桌面、半个货架、一张旧票、一个歪盆栽。
- 不做精致房间、精致餐厅、精致 UI、商业海报、潮流大片、3D 渲染。
- 中密度以上如果画场景，背景线条也要松，不要整齐到像建筑图或产品视觉。
- 延迟型隐喻允许画面第一眼有一点孤独、空、静，第二眼从道具关系读出分隔、筛选、校准、沉淀或发布。
- 如果画面只是空而没有动作或锚点，判定失败。

| 棋盘复盘 | 每一步选择都能回看和调整 | 策略复盘、取舍比较 | 棋盘一角和两枚棋子 |

## 动作局部规则

当密度是轻配图，画面只取一个最能表达动作的小局部。局部里可以有 2-4 个物件，但必须形成遮挡、翻找、露出、夹住、压住、撕开、抖落或修补关系；画面应该像“一个生活动作正在发生”，不是完整空间，也不是静物摆拍。

- 收音调频：只画一个旋钮、半截天线或一段波形，不画完整电台/雷达室。
- 裁缝试衣：只画布样、针线、量尺或一个补丁，不画完整试衣间。
- 暗房显影：只画显影盘、一张照片或一个夹子，不画完整暗房。
- 小店货架：只画一个小格口、一个价签或一个篮子，不画完整店铺。
- 地铁换乘：只画一个换乘点、站牌或短线路，不画完整地铁图。
- 微型街区：只画一个门牌、窗口或路口局部，不画整片城市。
- 舞台后台：只画场记板、幕布边角或一个道具架局部，不画发布会现场。
- 剪辑时间线：只画一个播放头、一小段胶片或 2-3 个剪辑片段，不画完整剪辑软件。
- 印刷拼版：只画一角裁切线、色标或打样纸，不画复杂印厂工作流。
- 图书馆索引：只画一个索引抽屉、书脊标签或借阅卡角落，不画整面书架。
- 影棚打光：只画一盏柔光灯、反光板或地面站位胶带，不画商业摄影棚。
- 温室育苗：只画一个小育苗盆、标签或浇水壶，不画完整花园。
- 陶艺修坯：只画一小块陶坯、修坯刀或转盘局部，不画完整手作工坊。
- 录音剪辑台：只画一段波形、一个推子或半只耳机，不画真实音频软件界面。
- 老式电话总机：只画一根插线、一个插孔或小标签，不画完整呼叫中心。
- 镜片校准：只画一片镜片、调节框或清晰/模糊对照，不画医疗诊室。
- 棋盘复盘：只画棋盘一角和 2-4 个棋子，不画完整比赛场景。

如果动作局部不足以讲清内容，升级到中密度解释图；不要在轻配图里硬塞完整场景。
低密度图必须在 prompt 中写出 `Everyday action metaphor`、`Occlusion relationship` 和 `Revealed clue`，并说明为什么不用信息载体直译。

## 留白和信息量偏好

载体选择后，再根据用户偏好调整尺度：

- 自动：按内容判断，不额外询问。
- 留白多：只保留载体局部，主体群占画布宽度 25%-38%、高度 20%-32%，四周至少 35% 空白安全边。
- 平衡：保留一个局部载体和少量上下文，主体群占画布宽度 35%-50%。
- 内容更丰富：可以展示更多载体上下文，但必须有分区和主阅读路径；如果没有分区，就拆成系列图。

同一个载体可以有不同信息量：例如“收音调频”在留白多模式只画一个旋钮和两段波形，在内容更丰富模式才画频谱、刻度、信号分类和输出结果。

## QA

失败信号：

- 同一系列看起来只是换了文字的纸笔图。
- 角色每次都拿笔、圈纸、贴便签。
- 载体说是控制台/地图/对话，但画面主体仍然是几张卡片。
- 只写了载体名称，没有写清“视觉隐喻动作”，画面像随机换场景。
- 把隐喻写成解释句，而不是用物件、动作和空间关系呈现。
- 画面只是道具摆拍，没有遮挡、翻找、露出、夹住、压住、撕开、抖落或修补关系。
- 只是把概念画成图标，或靠文字把隐喻讲出来。
- 隐喻太绕，需要读解释才懂，或者一个画面塞了多个隐喻。
- 低密度没有日常动作隐喻，直接画完整房间、完整餐厅、完整店铺、完整车站或完整工作台。
- 场景太精致，像商业插画、潮流大片、3D 渲染、UI mockup 或精致室内设计图。
- 延迟型隐喻只有空旷氛围，没有能慢慢读出的物件关系。
- 为了多样化加入无关摆件，核心动作反而不清楚。
- 所谓新颖载体只是换背景，信息仍然在纸片、卡片和文件夹里。
- 轻配图把新颖载体画成完整房间、完整街区、完整店铺或完整路线，导致画面天然变密。
- 主体群占满中间大部分画布，四周留白不够，画面看起来不精致。
- 新颖载体过度复杂，主体动作和核心意思被淹没。
- 使用真实平台 logo、真实 UI 或第三方品牌视觉。

合格信号：

- 低密度缩略图里能看出一个生活动作：某个东西被藏住、翻出、压住、夹住、露出或处理，四周留白明显。
- 中密度小场景粗糙、手作、不精修，信息关系仍然清楚。
- 延迟型隐喻第一眼有情绪，第二眼能从物件关系里读出内容关系。
