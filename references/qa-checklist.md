# QA Checklist

## 资产包检查

交付前逐项检查：

- `SKILL.md` frontmatter 有清楚触发词，且说明不是通用 Skill Creator。
- `SKILL.md` body 短，只包含定位、资源索引、工作流和边界。
- `style-dna.md` 至少有 5 个带证据的风格判断。
- `anti-style.md` 至少包含禁用词、禁用句式、禁用结构和失败信号。
- `content-patterns.md` 不只是一套模板，而是区分标题、开头、段落、结尾和平台变体。
- 如果用户强调去 AI 味或长期校准，`ai-flavor-diagnostics.md` 写清楚风险位置、问题类型、严重度和修复方向。
- 如果用户需要首跑、对比、评分、失败样本或内容改造，是否读取了 `experience-workflows.md` 并按对应模板输出。
- 如果内容依赖用户长期事实，`knowledge-cards.md` 只记录用户授权信息，并标出待确认信息。
- 如果用户多次反馈“不像我”，`style-evolution-log.md` 记录了反馈、新规则、影响文件和可信度。
- 如果有视觉主体，`ip-subject.md` 写清楚外形、性格、动作库、禁忌和参与核心动作的判断标准。
- 如果有长期固定视觉主体，`ip-subject.md` 写清楚参考图路径，且图片存在于 `assets/references/characters/`。
- 如果用户要使用自己的 IP，是否说明了短期可直接上传图，长期复用应放到 `assets/references/characters/<subject-slug>-reference.png`。
- 如果有视觉主体，`composition-patterns.md` 写清楚画面组织方式、隐喻发明步骤和避重规则。
- `examples/on-brand.md` 与 `examples/off-brand.md` 能解释为什么像或不像。
- 没有复刻名人、在世创作者、第三方 IP 或可识别案例构图。

## 输出内容检查

生成内容前问：

1. 这次任务属于写作、改写、标题、脚本、配图、UI 文案还是校准？
2. 是否读取了必要 references？
3. 是否保留事实，没有编造用户经历？
4. 是否避开了 anti-style？
5. 是否能指出至少 2 个“像用户”的具体原因？
6. 如果用户说“不像我”或“AI 味重”，是否先做诊断再修复，而不是直接重写？
7. 是否把修复方向绑定到用户自己的 `style-dna.md`、`anti-style.md`、`content-patterns.md` 或 `knowledge-cards.md`？
8. 如果用户只给一句短句，是否直接推断任务、平台和输出结构，而不是要求用户补完整提示词？
9. 如果短句里已有平台，是否按该平台输出尺寸、文案和配图规划？
10. 如果短句里没有平台，是否默认先做通用展示版，而不是追问平台？
11. 如果需要图中文字，是否由 Agent 从内容和平台自动提取短词，而不是要求用户手动提供 `Exact Chinese text allowed`？

短句入口额外检查：如果用户没有明确要求写文件、生成发布包或保存到项目，是否默认在聊天里给可发布内容、图片结果或缺素材提示，而不是创建或编辑 `.md` 文件。

短句入口生图检查：当前环境有生图能力时，是否主动生成图片，而不是只输出 prompt、规划或“可复制 prompt”？如果本机私有默认角色绑定生效，是否使用镇小宁作为主视觉主体；若只能文本生图，是否标注“方向预览，非最终 IP 一致性成稿”；是否不画真人肖像、不画普通蓝色角色、不画线团人、不画空心方盒和无角色图；失败时是否重试或要求上传参考图？

12. 如果是新手首跑，是否输出最小材料、会生成什么、第一轮测试任务和下一步，而不是长教程？
13. 如果是 Before/After，是否使用同一素材输出默认 AI 味版本、风格资产版本、改动说明和评分卡？
14. Before 是否可信，而不是故意写得很烂来衬托 After？
14. 如果是风格漂移评分，是否每个分数都有依据和修复建议？
15. 如果有低于 3 分的维度，是否进入失败样本库模式？
16. 如果用户反馈“不像我”“以后不要这样”，是否记录失败样本、新增规则、影响文件和修订小样？
17. 如果是一键内容改造，是否先区分可用事实和不可直接学习的部分？
17. 如果素材来自第三方文章、帖子或链接，是否只使用观点和事实，不提炼原作者风格、结构或标志性表达？
18. 如果生成配图，是否根据用户上传内容选择布局，而不是随机或沿用默认横向流程？
19. 如果用户上传或点名角色，是否锁定该角色识别点，而不是回退默认主体或只换颜色？
20. 如果用户本轮上传了角色图，是否优先使用当前上传图，而不是自动读取 `assets/references/characters/` 里的旧图？
21. 如果没有本轮上传图，但本机存在 `references/ip-subject.local.md` 且明确允许默认使用私有角色，是否优先读取这个本机绑定，而不是回退到默认主体？
22. 如果用户点名了具体角色但没有上传图、本机私有绑定、指定路径或绑定文件，是否先要求角色参考，而不是用默认主体顶替？
23. 如果读取固定参考图，是否有当前上传图、本机私有绑定、用户明确指定路径，或 `ip-subject.md` 明确绑定当前角色和该路径？
24. 如果使用固定 IP 生成最终成稿，是否把参考图作为实际图像参考输入或图像编辑输入，而不是只把识别点写进文字 prompt？
25. 如果当前生图工具不能接入参考图，但任务只是本机测试、自我介绍展示或方向预览，是否仍主动出图，并明确标注“方向预览 / 非最终 IP 一致性成稿”？
26. 如果当前环境能生图，是否真的调用生图，而不是停在 prompt、规划或说明？
26. 如果生成连续配图，是否全组使用同一个主视觉主体，而不是空心方盒、线团人、红章操作员等默认主体混用？
25. 如果生成配图，是否先判断密度档位：轻配图、中密度解释图或高密度工作台？
26. 当前画面是否符合所选密度预算：轻配图不堆信息，中密度有清晰分区，高密度有主阅读路径？
27. 低密度和高密度是否有缩略图级别的结构差异：低密度是一个小局部里的生活动作，高密度是一个系统？
28. 是否先判断了隐喻方式：秒懂型、延迟型或系统型？
29. 是否先选择了日常动作隐喻、遮挡关系、露出线索和视觉隐喻动作，而不是默认纸笔卡片？
30. 如果是轻配图，缩略图里是否能看出某个东西被藏住、翻出、压住、夹住、露出或处理，而不是完整复杂场景？
31. 如果使用场景，是否保持粗糙手绘感，而不是精致商业插画、3D 渲染或 UI mockup？
32. 缩略图继续看时能否看懂主体动作和核心意思；如果是延迟型，是否能越看越读出隐喻关系？
33. 如果生成连续配图，是否先给出 layout plan，且相邻图片没有重复布局？
34. 如果生成连续配图，相邻图片是否轮换了主要信息承载物，而不是连续使用纸片、卡片、便签或文件夹？
35. 如果生成连续配图，是否轮换了呈现载体：时间、操作面板、路线、空间剖面、对话、图鉴、实验检测、票据档案、舞台或生活实物？
36. 如果用户反馈“不够新颖”，是否至少给出 3 个新颖载体候选，并推荐 1 个？
37. 如果主题涉及流程卡点、素材复用、信息筛选、想法成型、经验沉淀或信任建立，是否避开了公开案例的物件组合和画面骨架，并说明替代空间关系？
38. 如果是轻配图，是否默认使用局部轻描，而不是完整房间、完整街区、完整工作台或完整系统？
39. 如果是轻配图，主体群是否只占画布中间一小块，四周有明显白边，批注没有变成大标题？
40. 如果生成配图，是否给出 `Exact Chinese text allowed`，并禁止模型自动新增标题、长句、段落或检查清单？
41. 如果 `Exact Chinese text allowed` 里有短词，是否默认把这些短词直接画进图里，而不是生成空白气泡、空白卡片、空白标签后再说本地字体排版？
41. 如果用户指定平台、封面、轮播、长图、视频封面、分享卡片或具体尺寸，是否读取 `platform-image-sizes.md` 并输出平台尺寸计划？
42. 平台尺寸计划是否包含平台/位置、推荐尺寸、比例、安全区和是否需要重排构图，而不是只写一个像素值？
43. 如果一图多平台，是否生成横版、竖版、方版等同源多版，而不是把同一张图裁切到所有平台？
44. 如果是公众号头图，关键文字、角色脸和核心道具是否在中心方形安全区？
45. 如果是小红书/Instagram 竖图，是否使用竖向上中下结构，而不是横向三栏硬塞？
46. 如果是 9:16 竖屏图，顶部和底部是否避开平台 UI 遮挡区？
47. 如果是窗口实验日志，是否先生成实验卡，而不是直接写生图 prompt？
48. 如果是窗口实验日志，是否过滤了隐私、密钥、账号、未授权素材和不适合公开的信息？
49. 如果是窗口实验日志，3-5 张图是否分别对应不同实验节点，而不是同一张聊天窗口换文字？

## 常见失败信号

- 输出只有“高级、温暖、有深度”这类空泛形容词。
- 写成通用爆款模板。
- 把“去 AI 味”做成泛泛改写，只替换词汇，不恢复用户自己的判断方式、节奏和材料。
- 承诺或暗示可以绕过 AI 检测器。
- 为了像人故意制造错别字、事实错误或低质量表达。
- 新手首跑变成超长说明文，用户仍不知道下一句该输入什么。
- 要求用户自己列图中文字、短词白名单或 `Exact Chinese text allowed`，而不是根据内容自动提取。
- 用户只想让 Skill 介绍自己，却被要求先选择平台、尺寸、密度或布局。
- 短句入口变成文件生成任务：用户只是说“我要发小红书 / X / 公众号”，却写了 `.md` 发布包，没有在聊天里给可用内容、图片结果或明确的缺素材提示。
- Before/After 对比里，Before 被故意写坏，After 加了用户没提供的经历或事实。
- 风格漂移评分全是高分，但没有证据、没有修复建议。
- 用户反馈“以后不要这样”，但没有生成失败样本记录、影响文件和下一次规则。
- 一键内容改造只是摘要原文，没有转成用户自己的发布内容。
- 第三方文章、帖子或链接被用来学习原作者风格、结构或标志性表达。
- 每个平台都用同一套语气。
- 反风格只写“不要 AI 味”，没有具体禁用词和结构。
- 视觉主体只是站在角落，没参与核心动作。
- 用户上传或点名角色，却使用空心方盒、线团人、红章操作员、墨点操作员或纸片工人等默认主体。
- 用户点名“镇小宁形象”“镇小宁 IP”“我的角色”或其他具体角色，但没有当前上传图、本机私有绑定或参考图时，仍用线团人、空心方盒等默认主体顶替。
- 本机已有 `references/ip-subject.local.md` 且允许默认使用私有角色时，仍提示缺少镇小宁/默认角色参考图，或改用默认主体。
- 本机已有 `references/ip-subject.local.md` 且允许默认使用私有角色，自我介绍展示却画成真人肖像、抽象人像、无角色图或普通蓝色角色。
- 本机已有 `references/ip-subject.local.md` 且允许默认使用私有角色，当前环境能生图却只输出 prompt 或规划，没有主动生成图片。
- 本机私有默认角色绑定生效时，没有使用镇小宁作为主视觉主体。
- 当前环境有生图能力时，只输出 prompt、规划、图片 Prompt 或让用户自行生图，没有主动生成图片。
- 文本生图只能做方向预览时，没有标注“非最终 IP 一致性成稿”，或把方向预览冒充为最终 IP 成稿。
- 把“更像你自己”理解成画真人肖像、拟真人头像、职业照或自拍感人物。
- 方向预览画成普通蓝色角色、通用蓝色吉祥物、线团人、空心方盒、无角色图或其他主体，却没有判定失败并重试。
- 本机已有 `references/ip-subject.local.md` 且允许默认使用私有角色，但最终成稿没有把参考图作为实际图像输入，只靠文字 prompt 生成了一个“长得像”的角色。
- 生成图只保留了颜色、红鼻子或黄色耳朵，物种轮廓、眼睛比例、耳朵位置、肚皮形状和整体气质已经偏离参考图，却仍声称是固定 IP。
- 当前工具不能接入参考图时，仍然继续生成固定 IP 成稿，而不是提示限制。
- 用户本轮上传了自己的 IP 图，却自动改用 `assets/references/characters/` 里的旧图或其他项目图。
- 未经当前上传、用户明确指定路径、`ip-subject.local.md` 或 `ip-subject.md` 绑定，就扫描并使用固定目录里的角色图。
- 同一组连续配图混用多个主视觉主体，导致角色资产不稳定。
- 长期固定 IP 没有参考图路径，或参考图不在 `assets/references/characters/`。
- 用户想用自己的 IP，却没有提醒短期上传图和长期固定目录的区别。
- 画面像资料墙、便签墙或复杂关系图，信息过密，需要放大才能看懂。
- 为了表现“真实材料”，把网页、便签、纸条、缩略图、红线、批注全部塞进同一张。
- 用户只是要正文配图，却输出了高密度工作台。
- 用户只是要正文配图，却把新颖载体画成完整场景，导致画面天然变密。
- 低密度配图没有日常动作隐喻，直接画完整房间、餐厅、便利店、车站、工作室或城市。
- 中密度解释图画了完整复杂场景，却没有说明为什么不用小范围粗糙场景。
- 场景过于精致，像商业插画、3D 渲染、UI mockup、潮流大片、精致室内设计或美食广告。
- 所谓粗糙感变成低质量：核心动作不清楚、结构混乱、物件看不出是什么。
- 延迟型隐喻只剩孤独和氛围，没有任何可读的物件关系或内容线索。
- 秒懂型隐喻太绕，需要读长解释才能理解。
- 看起来像图标说明、PPT 插图或道具摆拍，物件之间没有遮挡、翻找、露出、夹住、压住、撕开、抖落或修补关系。
- 文字比动作更重要，必须读批注才知道图在表达什么。
- 画面元素虽然不多，但主体群过大、贴近边缘、外圈留白不足，看起来不精致。
- 红字批注过大，像标题或海报文案，而不是小手写注。
- 图片中文字没有遵守白名单，自动生成了长句、标题、段落、检查清单或未要求的解释。
- 已经给了短词白名单，但图里所有气泡、标签、卡片、便签或纸条都是空白，文字被推迟到“后期本地排版”。
- 用户要求复盘、方法论、PPT 或无限画布，却只给了过于简单的轻配图。
- 高密度画面没有分区、主阅读路径和留白，只是把信息堆满。
- 低密度和高密度只是在纸片、文字和箭头数量上不同，缩略图结构看起来差不多。
- 连续两张都主要靠纸片、卡片、便签或文件夹承载信息。
- 一组图里角色总是在拿笔、圈纸、贴便签，没有操作面板、路线、对话、时间、剖面、图鉴、实验检测、票据档案、舞台或生活实物等载体变化。
- 所谓新颖载体只是换背景，信息仍然主要放在纸片、卡片和文件夹里。
- 载体只有场景名，没有隐喻方式、日常动作隐喻、遮挡关系、露出线索和视觉隐喻动作。
- 用户要求更新颖，但仍只在基础载体里选择，没有先给掀、夹、压、揉、撕、抖、晾、补、泡、沉、捞、贴住等日常动作候选。
- 诊断点很多时，把每个问题都画出来，而不是只选择一个核心动作。
- 连续配图都像“左边输入、中间主体、右边输出卡片”，只是换了标签。
- 同一系列反复使用相同道具，例如每张都是箱子、三张卡片、直线箭头。
- 说是自动选择布局，但没有说明内容信号、选择理由和避重理由。
- 说要适配小红书、公众号、X 或竖屏平台，但仍只输出默认 16:9。
- 把横图直接裁成竖图，导致角色脸、奖杯、中文短词或核心道具出安全区。
- 公众号头图没有中心方形安全区，分享缩略图看不懂。
- 小红书轮播多张图比例不一致。
- 9:16 竖屏图把重要文字放在顶部或底部 UI 遮挡区。
- 只写“1080x1440”，没有说明平台位置、比例、安全区和是否要重排构图。
- 用户上传的是截图、网页、表格、角色图或长文，却没有根据材料形态调整布局。
- 遇到流程、复用、筛选、沉淀、信任主题时，直接套用公开案例式物件组合、主体动作或画面骨架。
- 只是更换角色或颜色，但画面骨架、主体动作和信息承载物仍然像公开案例。
- 窗口实验日志把整段聊天记录、账号信息、密钥、私密路径或未授权第三方素材画进图里。
- 窗口实验日志只是在画聊天框、文件树或截图，没有提炼起因、卡点、选择、结果和下一步。
- 直接仿名人、博主、画师或第三方 IP。
- 把用户没有提供的信息写成事实。

## 校准流程

用户反馈“不像我”时，不要直接重写一版。先拆成三类问题：

- **事实不对**：补充或删除事实。
- **风格漂移**：更新 `style-dna.md` 或 `anti-style.md`。
- **任务误判**：调整平台、受众、内容结构或视觉主体。
- **AI 味回潮**：读取 `ai-flavor-diagnostics.md`，确认是词汇、结构、节奏、事实、视觉质感还是主体动作出了问题。
- **画面过密**：保留一个核心动作，删除多余材料、箭头、批注和次要功能；必要时拆成系列图。
- **密度误判**：根据平台和用户目标重选轻配图、中密度解释图或高密度工作台。
- **尺寸误判**：读取 `platform-image-sizes.md`，重新选择平台尺寸、比例和安全区；涉及文字、角色脸或核心道具时重排构图，不直接裁切。
- **尺度过大**：不先删核心信息，先把主体群缩小到画布宽度 30%-40%、高度 25%-35%，四周保留至少 30% 空白安全边。
- **完整场景误用**：把完整房间、完整街区、完整店铺或完整路线改成载体局部，例如旋钮、布样、显影盘、小格口、站牌、门牌或按钮。
- **低密度场景误用**：把完整场景缩成一个小局部里的动作关系，例如找信息改成从被子下面摸出皱纸条，筛需求改成抖旧桌布留下有用颗粒，去 AI 味改成揉皱光滑稿纸再贴补丁，社媒反馈改成用胶带贴住吵闹红点。
- **场景过精致**：降低完成度和商业感，增加歪线、轻微透视错误、粗糙边缘、草稿阴影和手绘痕迹，但保留核心动作清楚。
- **文字漂移**：把 prompt 改成 `Exact Chinese text allowed` 白名单，只允许短词；删除长句、标题、段落和检查清单。
- **文字漏画**：如果白名单短词没有进图，重写 prompt 为“directly draw these exact short Chinese handwritten notes”，并减少短词数量；只有用户要求最终排版或模型连续写坏字时，才使用无字底图加本地字体。

## 视觉隐喻规划自测样例

不需要直接生图，先检查布局规划是否符合隐喻规则。

| 测试主题 | 推荐规划 | 必须检查 |
| --- | --- | --- |
| 找信息 | 轻配图 / 延迟型 / 用户角色从被子一角下面摸出皱纸条 | 不是搜索框；不是资料墙；能看出“被藏住又被翻出” |
| 筛真实需求 | 轻配图 / 秒懂型 / 用户角色抖旧桌布，杂物落下，只剩几颗亮点 | 不画直白筛子图标；筛选动作要清楚 |
| 去 AI 味 | 轻配图或中密度 / 延迟型 / 太光滑的稿纸被揉皱后摊开，边上贴手写补丁 | 不画完整剪辑软件；不靠“剪掉 AI 味”大字解释 |
| 平台适配 | 中密度 / 秒懂型 / 同一张小图被塞进三个不同大小的旧相框，露出的边角不同 | 不画完整印刷厂；能看出重排和裁切关系 |
| 长期养成 | 轻配图 / 延迟型 / 旧杯子里的小苗旁边贴着一层层旧日期标签 | 不画完整温室；不能只有治愈氛围，必须有时间痕迹 |
| 社媒反馈 | 轻配图 / 延迟型 / 一个吵闹小红点被胶带贴住，旁边露出一条真正有用的纸条 | 不画真实平台 UI；不满屏弹幕；能读出噪声被控制 |
