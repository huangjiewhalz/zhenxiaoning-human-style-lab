# QA Checklist

## 资产包检查

交付前逐项检查：

- `SKILL.md` frontmatter 有清楚触发词，且说明不是通用 Skill Creator。
- `SKILL.md` body 短，只包含定位、资源索引、工作流和边界。
- `style-dna.md` 至少有 5 个带证据的风格判断。
- `anti-style.md` 至少包含禁用词、禁用句式、禁用结构和失败信号。
- `content-patterns.md` 不只是一套模板，而是区分标题、开头、段落、结尾和平台变体。
- 如果用户强调去 AI 味或长期校准，`ai-flavor-diagnostics.md` 写清楚风险位置、问题类型、严重度和修复方向。
- 如果内容依赖用户长期事实，`knowledge-cards.md` 只记录用户授权信息，并标出待确认信息。
- 如果用户多次反馈“不像我”，`style-evolution-log.md` 记录了反馈、新规则、影响文件和可信度。
- 如果有视觉主体，`ip-subject.md` 写清楚外形、性格、动作库、禁忌和参与核心动作的判断标准。
- 如果有视觉主体，`composition-patterns.md` 写清楚画面组织方式、隐喻发明步骤和避重规则。
- `examples/on-brand.md` 与 `examples/off-brand.md` 能解释为什么像或不像。
- 没有复刻名人、在世创作者、第三方 IP 或可识别案例构图。

## 输出内容检查

生成内容前问：

1. 这次任务属于写作、改写、标题、脚本、配图、UI 文案还是校准？
2. 是否读取了必要 references？
3. 是否保留事实，没有编造用户经历？
4. 是否避开了 anti-style？
5. 是否能指出至少 2 个“像用户”的具体原因？
6. 如果用户说“不像我”或“AI 味重”，是否先做诊断再修复，而不是直接重写？
7. 是否把修复方向绑定到用户自己的 `style-dna.md`、`anti-style.md`、`content-patterns.md` 或 `knowledge-cards.md`？
8. 如果生成配图，是否根据用户上传内容选择布局，而不是随机或沿用默认横向流程？
9. 如果用户上传或点名角色，是否锁定该角色识别点，而不是回退默认主体或只换颜色？
10. 如果生成配图，是否先判断密度档位：轻配图、中密度解释图或高密度工作台？
11. 当前画面是否符合所选密度预算：轻配图不堆信息，中密度有清晰分区，高密度有主阅读路径？
12. 低密度和高密度是否有缩略图级别的结构差异：低密度是一个动作，高密度是一个系统？
13. 是否先选择了呈现载体，而不是默认纸笔卡片？
14. 缩略图下一眼能否看懂主体动作和核心意思？
15. 如果生成连续配图，是否先给出 layout plan，且相邻图片没有重复布局？
16. 如果生成连续配图，相邻图片是否轮换了主要信息承载物，而不是连续使用纸片、卡片、便签或文件夹？
17. 如果生成连续配图，是否轮换了呈现载体：时间、操作面板、路线、空间剖面、对话、图鉴、实验检测、票据档案、舞台或生活实物？
18. 如果用户反馈“不够新颖”，是否至少给出 3 个新颖载体候选，并推荐 1 个？
19. 如果主题涉及流程卡点、素材复用、信息筛选、想法成型、经验沉淀或信任建立，是否避开了公开案例的物件组合和画面骨架，并说明替代空间关系？
20. 如果是轻配图，是否默认使用局部轻描，而不是完整房间、完整街区、完整工作台或完整系统？
21. 如果是轻配图，主体群是否只占画布中间一小块，四周有明显白边，批注没有变成大标题？
22. 如果生成配图，是否给出 `Exact Chinese text allowed`，并禁止模型自动新增标题、长句、段落或检查清单？
23. 如果用户指定平台、封面、轮播、长图、视频封面、分享卡片或具体尺寸，是否读取 `platform-image-sizes.md` 并输出平台尺寸计划？
24. 平台尺寸计划是否包含平台/位置、推荐尺寸、比例、安全区和是否需要重排构图，而不是只写一个像素值？
25. 如果一图多平台，是否生成横版、竖版、方版等同源多版，而不是把同一张图裁切到所有平台？
26. 如果是公众号头图，关键文字、角色脸和核心道具是否在中心方形安全区？
27. 如果是小红书/Instagram 竖图，是否使用竖向上中下结构，而不是横向三栏硬塞？
28. 如果是 9:16 竖屏图，顶部和底部是否避开平台 UI 遮挡区？
29. 如果是窗口实验日志，是否先生成实验卡，而不是直接写生图 prompt？
30. 如果是窗口实验日志，是否过滤了隐私、密钥、账号、未授权素材和不适合公开的信息？
31. 如果是窗口实验日志，3-5 张图是否分别对应不同实验节点，而不是同一张聊天窗口换文字？

## 常见失败信号

- 输出只有“高级、温暖、有深度”这类空泛形容词。
- 写成通用爆款模板。
- 把“去 AI 味”做成泛泛改写，只替换词汇，不恢复用户自己的判断方式、节奏和材料。
- 承诺或暗示可以绕过 AI 检测器。
- 为了像人故意制造错别字、事实错误或低质量表达。
- 每个平台都用同一套语气。
- 反风格只写“不要 AI 味”，没有具体禁用词和结构。
- 视觉主体只是站在角落，没参与核心动作。
- 画面像资料墙、便签墙或复杂关系图，信息过密，需要放大才能看懂。
- 为了表现“真实材料”，把网页、便签、纸条、缩略图、红线、批注全部塞进同一张。
- 用户只是要正文配图，却输出了高密度工作台。
- 用户只是要正文配图，却把新颖载体画成完整场景，导致画面天然变密。
- 画面元素虽然不多，但主体群过大、贴近边缘、外圈留白不足，看起来不精致。
- 红字批注过大，像标题或海报文案，而不是小手写注。
- 图片中文字没有遵守白名单，自动生成了长句、标题、段落、检查清单或未要求的解释。
- 用户要求复盘、方法论、PPT 或无限画布，却只给了过于简单的轻配图。
- 高密度画面没有分区、主阅读路径和留白，只是把信息堆满。
- 低密度和高密度只是在纸片、文字和箭头数量上不同，缩略图结构看起来差不多。
- 连续两张都主要靠纸片、卡片、便签或文件夹承载信息。
- 一组图里角色总是在拿笔、圈纸、贴便签，没有操作面板、路线、对话、时间、剖面、图鉴、实验检测、票据档案、舞台或生活实物等载体变化。
- 所谓新颖载体只是换背景，信息仍然主要放在纸片、卡片和文件夹里。
- 用户要求更新颖，但仍只在基础载体里选择，没有给微型街区、地铁换乘、暗房显影、收音调频、邮局分拣、裁缝试衣、厨房备料、博物馆展柜、舞台后台、天气观测、沙盘推演、小店货架、维修工位或观测星图等候选。
- 诊断点很多时，把每个问题都画出来，而不是只选择一个核心动作。
- 连续配图都像“左边输入、中间主体、右边输出卡片”，只是换了标签。
- 同一系列反复使用相同道具，例如每张都是箱子、三张卡片、直线箭头。
- 说是自动选择布局，但没有说明内容信号、选择理由和避重理由。
- 说要适配小红书、公众号、X 或竖屏平台，但仍只输出默认 16:9。
- 把横图直接裁成竖图，导致角色脸、奖杯、中文短词或核心道具出安全区。
- 公众号头图没有中心方形安全区，分享缩略图看不懂。
- 小红书轮播多张图比例不一致。
- 9:16 竖屏图把重要文字放在顶部或底部 UI 遮挡区。
- 只写“1080x1440”，没有说明平台位置、比例、安全区和是否要重排构图。
- 用户上传的是截图、网页、表格、角色图或长文，却没有根据材料形态调整布局。
- 遇到流程、复用、筛选、沉淀、信任主题时，直接套用公开案例式物件组合、主体动作或画面骨架。
- 只是更换角色或颜色，但画面骨架、主体动作和信息承载物仍然像公开案例。
- 窗口实验日志把整段聊天记录、账号信息、密钥、私密路径或未授权第三方素材画进图里。
- 窗口实验日志只是在画聊天框、文件树或截图，没有提炼起因、卡点、选择、结果和下一步。
- 直接仿名人、博主、画师或第三方 IP。
- 把用户没有提供的信息写成事实。

## 校准流程

用户反馈“不像我”时，不要直接重写一版。先拆成三类问题：

- **事实不对**：补充或删除事实。
- **风格漂移**：更新 `style-dna.md` 或 `anti-style.md`。
- **任务误判**：调整平台、受众、内容结构或视觉主体。
- **AI 味回潮**：读取 `ai-flavor-diagnostics.md`，确认是词汇、结构、节奏、事实、视觉质感还是主体动作出了问题。
- **画面过密**：保留一个核心动作，删除多余材料、箭头、批注和次要功能；必要时拆成系列图。
- **密度误判**：根据平台和用户目标重选轻配图、中密度解释图或高密度工作台。
- **尺寸误判**：读取 `platform-image-sizes.md`，重新选择平台尺寸、比例和安全区；涉及文字、角色脸或核心道具时重排构图，不直接裁切。
- **尺度过大**：不先删核心信息，先把主体群缩小到画布宽度 30%-40%、高度 25%-35%，四周保留至少 30% 空白安全边。
- **完整场景误用**：把完整房间、完整街区、完整店铺或完整路线改成载体局部，例如旋钮、布样、显影盘、小格口、站牌、门牌或按钮。
- **文字漂移**：把 prompt 改成 `Exact Chinese text allowed` 白名单，只允许短词；删除长句、标题、段落和检查清单。

每次校准都输出：

```markdown
## 本次漂移点

## AI 味诊断

## 需要更新的资产文件

## 新规则

## 修订后示例
```

## 展示案例检查

适合展示的案例应该包含：

- 默认 AI 输出。
- 使用风格资产后的输出。
- 3 条差异解释。
- 用户可以一眼看出的风格主体或反风格变化。
