# Style DNA Schema

用于生成 `references/style-dna.md`。每个判断尽量写证据，不要只写形容词。

## 文件结构

```markdown
# Style DNA

## 一句话风格判断

## 证据来源

## 语气与人格

## 句子节奏

## 隐喻和例子

## 平台变体

## 待校准假设
```

## 一句话风格判断

写成可执行判断，而不是抽象夸奖。

好：

- 短句、克制、先判断后解释，偏产品经理式拆解，不做情绪煽动。
- 像在白纸上把复杂事拆成小机器，少废话，有一点冷幽默。

差：

- 文风很好，很有个人特色。
- 有高级感、有温度、有深度。

## 证据来源

列出样本：

```markdown
| 样本 | 类型 | 主要证据 | 可信度 |
| --- | --- | --- | --- |
| 作品 1 | 公众号文章 | 标题短、开头先下判断 | 高 |
| 作品 2 | 小红书笔记 | 口语化、有真实吐槽 | 中 |
```

可信度：

- 高：多个样本反复出现。
- 中：2 个样本出现。
- 低：单一样本或用户口头偏好。

## 语气与人格

提炼：

- 对读者的距离：朋友、顾问、旁观者、操盘手、研究员。
- 情绪强度：冷、稳、锋利、陪伴、松弛、兴奋。
- 说服方式：案例、判断、步骤、反问、故事、对比、清单。

必须写：

- 要保留什么。
- 要避免什么。

## 句子节奏

关注：

- 长句还是短句。
- 段落长度。
- 是否常用冒号、破折号、括号、编号。
- 是否喜欢先给结论。
- 是否允许口语停顿。

输出示例：

```markdown
- 句子偏短，单句通常只承载一个判断。
- 段落 1-3 行为主，适合移动端扫读。
- 可以用冒号引出判断，但少用排比式总结。
```

## 词汇偏好

写成词库和禁用词的关系。

```markdown
常用词：判断、证据、闭环、校准、真实、默认、拆开、沉淀。
慎用词：赋能、抓手、矩阵、私域、爆款、颠覆、全网。
```

## 内容结构

提炼用户常用的组织方式：

- 痛点 -> 判断 -> 拆解 -> 例子 -> 行动。
- 现象 -> 反常识 -> 机制 -> 结论。
- 问题 -> 风险 -> 边界 -> 最小方案。

每种结构写适用场景，不要让所有内容都套同一模板。

## 标题与开头

标题维度：

- 是否直给痛点。
- 是否用数字。
- 是否保留悬念。
- 是否有口语化判断。

开头维度：

- 先讲场景还是先给结论。
- 是否允许吐槽。
- 是否避免宏大背景。

## 判断方式

记录用户如何表达观点：

- 先说“不是什么”，再说“是什么”。
- 先收窄边界，再给结论。
- 先指出风险，再给可执行方案。
- 不轻易说绝对话，给条件和适用范围。

## 隐喻和例子

提炼用户喜欢的比喻来源：

- 工具、机器、工位、白纸、盒子、路径、地图、证据、样本。
- 少用宇宙、魔法、战争、玄学等不贴合主题的隐喻，除非用户样本中反复出现。

## 视觉审美

如果用户需要视觉资产，记录：

- 画面密度。
- 色彩范围。
- 主体形态。
- 是否需要固定 IP 主体。
- 字体/手写/标注偏好。
- 禁止的视觉套路。

## 平台变体

同一风格在不同平台要变形，不要原样复制：

- 公众号：结构更完整，段落解释更充分。
- 小红书：标题更具体，开头更快进入痛点。
- B 站脚本：多保留口语停顿和画面提示。
- 产品文案：压缩形容词，强化承诺、边界和动作。

## 待校准假设

没有足够证据的内容放这里：

```markdown
- 假设用户接受轻微冷幽默，需要后续用 3 条新内容测试。
- 假设视觉主体可以偏黑色手绘，但还没有用户原创主体证据。
```
