# Model Runtime Requirements

用于判断当前环境能把个人风格资产执行到什么程度。这个 Skill 本体不绑定任何单一模型；它定义的是工作流、风格资产、布局选择和合规边界。

## 能力层级

### 文本模型

可完成：

- 读取用户文字作品、偏好和反风格要求。
- 生成 `style-dna.md`、`anti-style.md`、`content-patterns.md`、`prompt-template.md`、`qa-checklist.md`。
- 需要风格回归时生成 `ai-flavor-diagnostics.md`、`knowledge-cards.md` 和 `style-evolution-log.md`。
- 根据文章内容生成配图布局计划、密度档位和生图 prompt。
- 根据目标平台生成尺寸计划、比例、安全区和多平台重排 prompt。
- 在能读取当前对话上下文时，整理窗口实验日志、实验卡、3-5 张系列图布局表和生图 prompt。

不能独立完成：

- 可靠识别用户上传角色图、截图或视觉作品。
- 直接生成图片文件。
- 检查生成图片是否真的符合角色和布局。
- 在没有上下文权限或用户没有提供摘要时，完整还原“当前窗口”的历史内容。

降级方式：先提示用户“当前模型/环境不能直接生成图片”，再明确交付“图像生成提示词”和“布局计划”，不要声称已生成图片。

如果用户要求“把当前窗口做成图”，但当前环境读不到完整窗口，先提示用户需要粘贴窗口摘要、关键对话或项目路径，再继续整理。

### 多模态理解模型

额外可完成：

- 读取用户上传的角色图、截图、网页截图、视觉作品和配图样例。
- 提炼视觉主体特征、画风证据、构图偏好、密度偏好和反风格失败信号。
- 对生成图做初步 QA，例如角色是否跑偏、文字是否过密、密度档位是否误判、布局是否重复。

仍然需要：

- 如果要输出真实图片文件，还需要接入生图模型或外部图片生成工具。

### 生图模型

用于把 `visual-style-seed.md`、`ip-subject.md`、`composition-patterns.md`、密度档位和单张 prompt 转成图片。

最低要求：

- 支持文本到图像。
- 支持常见社媒比例：16:9、3:4、4:5、1:1、9:16、2.35:1 或接近这些比例的输出。
- 能遵守白底、手绘、留白、短中文批注和轻/中/高密度档位等约束。
- 能尝试把 `Exact Chinese text allowed` 里的短中文直接画成手写批注、云朵短词、小标签或纸角字迹；这些短词由 Agent 从内容自动提取，不要求用户手动列词；不要默认生成空白文字框。

限制：

- 仅支持文本到图像的模型，可以生成原创主体或临时方向预览图，但不能保证固定 IP 一致性。
- 当用户要求最终成稿、严格一致、官方发布图，且需要使用当前上传角色、本机私有默认角色、指定路径角色或 `ip-subject.md` 绑定角色时，文本到图像不够用；必须使用支持参考图输入或图像编辑的模型。

更好要求：

- 支持参考图输入，用于保持用户上传角色的识别点。
- 支持图像编辑或局部重绘，用于修正文字、角色比例、构图重复和小错误。
- 支持批量或连续生成，用于 3-10 张系列配图。

### 图像编辑模型

适合：

- 保留用户角色，只改动作、道具、场景或画风。
- 删除错误文字。
- 调整局部构图。
- 统一一组图的角色比例和画面密度。

如果没有图像编辑能力，只能重新生成整张图，角色一致性会更不稳定。

## 推荐执行链路

1. 文本/多模态模型读取用户材料。
2. 生成 Style DNA、反风格清单、视觉主体、平台尺寸计划、密度档位、布局计划和每张图的短词白名单。
3. 文本/多模态模型把每张图写成明确 scene plan，并说明平台/位置、尺寸比例、安全区、自动提取的 `Exact Chinese text allowed`、角色-场景画风协同和是否需要重排构图。若使用抽象镇小宁涂鸦风，scene plan 必须说明场景、道具、信息载体和批注也采用同一乱线彩铅/蜡笔/铅笔草稿语言，不使用写实桌面、照片物件、产品样机或真实 UI。
4. 如果使用固定 IP，先确认生图/改图工具能否接入参考图；能接入时，把当前上传图或绑定路径图片作为实际图像参考输入。抽象镇小宁若绑定了唯一母版，必须使用这张母版作为实际输入或图像编辑来源。不能接入但只是本机快速测试、自我介绍展示或方向预览时，普通固定角色可以主动生成方向预览图并标注非最终成稿；抽象镇小宁固定风格不要文本重画，优先直接展示/引用唯一母版作为抽象风格小图，或要求用户把母版图上传到当前对话后再生成变体。若用户要求最终一致性，则停止出图，说明限制并输出文案、布局和可复制 prompt。
5. 生图模型生成图片。
6. 多模态模型或人工检查角色、布局、文字、角色-场景画风协同、平台裁切安全区、公开案例避让和反 AI 味。如果生成图已经自然画入可读、贴合内容且不跑偏的短中文批注，文字部分视为通过，不再叠加标题、副标题、说明条或本地字体。如果白名单短词完全没有进图，或关键短词错到影响理解，优先减少短词并重生成；仍不稳定时交付少字/无字图加图外说明，不做本地排版。如果角色只是“像”参考图而不是参考图身份延续，判定失败。如果自动密度导致固定角色或抽象镇小宁识别点不清，先降低密度、减少短词和道具、拆成系列或放大角色，再重试；不要把信息密度正确但角色不一致的图片交付为成功。若抽象镇小宁的角色是乱线彩铅而场景变成写实桌面、照片物件、产品样机或真实 UI，判定为画风割裂并重试。若选择抽象镇小宁但角色本体仍是干净普通卡通，只是在旁边加涂鸦云、乱线背景、抽象道具或“AI 味”线团，判定为抽象失败；重试时减少解释性元素，优先把角色本体推近唯一母版。
7. 需要时用图像编辑模型局部修正。

风格候选测试链路：

- 用户说“测试一下”“看看效果”“用这段内容试试”且没有指定单一风格时，先生成三种候选，而不是只生成系统推荐的主风格。
- 三种候选按不同任务生成：白底彩铅解释观点和机制，抽象镇小宁表达一个状态/情绪，虚实结合呈现现实证据或工作现场。
- 当前环境有生图能力时，主动生成可生成的候选图，不用 prompt 代替图片。
- 固定 IP 参考图不能接入时，普通固定角色候选标注为方向预览；抽象镇小宁若有唯一母版且不能接入，则直接展示/引用母版图，不文本生图重画。
- 某一种候选受工具限制时，说明限制并继续完成其他候选；结束时给出推荐锁定风格。

图中文字处理规则：

- 默认：短中文直接由生图模型画入图中，保持手写感和草稿感。生成后如果这些短词已经可读并且没有明显跑题，保留原图，不再二次叠字。
- 禁止：不使用本地排版、Pillow、ImageMagick、本地字体、截图叠字或“无字底图 + 本地字体排版”补字；不要因为工具可用就额外添加标题、副标题或说明条。
- 失败处理：如果关键短词写坏或漏画，先减少短词数量并重生成；仍失败时交付少字/无字图，把准确文字放在聊天正文、图片说明或发布文案里，不在本机补字。

窗口实验日志链路：

1. 读取当前窗口、用户提供的摘要或项目材料。
2. 生成实验卡，过滤不适合公开的信息。
3. 选择 3-5 张叙事节点、密度档位、隐喻方式、日常动作隐喻、遮挡关系、露出线索、呈现载体、视觉隐喻动作和布局。
4. 读取 `platform-image-sizes.md` 选择目标尺寸、比例和安全区。
5. 有生图能力时生成图片；没有时输出可复制 prompt。

## 当前 Codex 环境

在当前 Codex 环境中，生图依赖外层 `imagegen` / `image_gen` 能力。这个能力不属于 `style-avatar-workshop` 文件夹本身。

因此，复制本 Skill 到没有生图工具的环境时，它仍然可以产出个人风格资产和图片 prompt，但不能自己生成图片文件。

如果外层生图工具不能接收本地参考图或当前对话上传图作为图像输入，则它不适合生成固定 IP 最终成稿。自我介绍展示或快速测试仍可生成方向预览图，但必须主动 QA，发现人像、普通蓝色角色、耳朵/鼻子/肚皮/眼睛明显偏离时重试或要求上传参考图。

如果当前工具列表里存在 `imagegen`、`image_gen` 或等价生图工具，就视为“当前环境有生图能力”。短句入口、自我介绍展示、通用展示版和本机快速测试遇到配图任务时，必须主动生成图片，不要只输出 prompt、规划或“可以拿去生成”的说明。

当本机私有默认角色绑定生效时：

- 能接入参考图：使用私有默认角色参考图生成正式 IP 成稿。
- 抽象镇小宁且有唯一母版：优先使用这张母版作为实际输入，不能只靠文字重新发明抽象画法，也不能临时换其它抽象版本。
- 不能接入参考图但可以文本生图：主动生成“方向预览图”，并标注 `方向预览，非最终 IP 一致性成稿`。
- 不能接入参考图但可以文本生图时，上一条只适用于普通固定角色方向预览；抽象镇小宁固定风格已有唯一母版时，不文本重画新抽象角色，直接展示/引用母版图或要求上传母版图。
- 方向预览也必须使用私有默认角色作为主视觉主体，不画真人肖像、不画普通蓝色角色、不画抽象人像/真人替身、不画无角色图、不画线团人、不画空心方盒。若该私有默认角色是镇小宁，必须保留红鼻子、白肚皮、黄色长耳/触角、大眼睛和蓝色圆润小兽轮廓；用户明确要求“抽象镇小宁”时，允许做镇小宁的抽象涂鸦变体，但不改变主体身份。
- 如果用户明确接受“无母版输入的松散方向预览”，才按密度自动调尺度：轻配图/自我介绍/方向预览优先 26%-34%，中密度 22%-30%，高密度 20%-26% 且必须仍能看清识别点；如果不通过，自动降密度、减少信息或拆图。
- 如果用户明确接受“无母版输入的松散方向预览”，场景也要抽象化：道具、信息载体、线缆、纸片和短词批注与角色使用同一乱线彩铅/蜡笔草稿画风。除非用户明确要求虚实结合，不使用写实桌面、真实照片物件、摄影棚阴影、产品样机、真实 UI 或 stock photo 场景。
- 如果用户要求抽象镇小宁固定风格，而当前工具不能接入唯一母版，不要文本重画；展示/引用固定母版图，或要求用户上传母版图。不得说文本生图结果是基于唯一母版的最终一致版本。
- 多风格对比中若抽象母版不能接入生图工具，抽象那张使用固定母版展示图，不生成新的普通蓝色卡通。
- 如果方向预览跑成其他主体，先重试；重试仍失败时，要求用户上传镇小宁参考图或换支持参考图/图像编辑的工具。

## 无生图能力时的用户提示

当用户要求“生成图片”“出图”“画一张”“做配图”，但当前环境没有生图工具或生图模型时，必须先说清楚限制，再给可执行替代物。

推荐话术：

```text
当前模型/环境不能直接生成图片。我可以先按你的文章和角色生成布局方案与可复制的生图 prompt；你可以把 prompt 放到可用的生图工具里生成图片。
```

窗口实验日志推荐话术：

```text
当前模型/环境不能直接生成图片。我可以先把这个窗口整理成实验卡、3-5 张手绘图布局计划和可复制的生图 prompt；有生图工具时再把这些 prompt 生成图片。
```

不要这样说：

- “已生成图片”，但实际只给了 prompt。
- “图片在附件里”，但没有真实图片文件。
- 不说明能力限制，直接输出一组 prompt。

## 写入子 Skill 时

生成个人风格子 Skill 时，如果用户需要配图，应该在 `prompt-template.md` 或 `composition-patterns.md` 里说明：

- 有生图工具时：按布局计划和密度档位生成图片。
- 有平台尺寸要求时：按 `platform-image-sizes.md` 先生成平台尺寸计划，不把 16:9 图简单裁切成其他比例。
- 没有生图工具时：先提示用户当前模型/环境不能直接生成图片，再输出可复制到生图工具的 prompt，prompt 里必须包含尺寸、比例和安全区。
- 有多模态能力时：先读取用户角色图并提取识别点。
- 没有多模态能力时：要求用户用文字描述角色，或只输出待校准假设。
