# Model Runtime Requirements

用于判断当前环境能把个人风格资产执行到什么程度。这个 Skill 本体不绑定任何单一模型；它定义的是工作流、风格资产、布局选择和合规边界。

## 能力层级

### 文本模型

可完成：

- 读取用户文字作品、偏好和反风格要求。
- 生成 `style-dna.md`、`anti-style.md`、`content-patterns.md`、`prompt-template.md`、`qa-checklist.md`。
- 需要风格回归时生成 `ai-flavor-diagnostics.md`、`knowledge-cards.md` 和 `style-evolution-log.md`。
- 根据文章内容生成配图布局计划、密度档位和生图 prompt。
- 在能读取当前对话上下文时，整理窗口实验日志、实验卡、3-5 张系列图布局表和生图 prompt。

不能独立完成：

- 可靠识别用户上传角色图、截图或视觉作品。
- 直接生成图片文件。
- 检查生成图片是否真的符合角色和布局。
- 在没有上下文权限或用户没有提供摘要时，完整还原“当前窗口”的历史内容。

降级方式：先提示用户“当前模型/环境不能直接生成图片”，再明确交付“图像生成提示词”和“布局计划”，不要声称已生成图片。

如果用户要求“把当前窗口做成图”，但当前环境读不到完整窗口，先提示用户需要粘贴窗口摘要、关键对话或项目路径，再继续整理。

### 多模态理解模型

额外可完成：

- 读取用户上传的角色图、截图、网页截图、视觉作品和配图样例。
- 提炼视觉主体特征、画风证据、构图偏好、密度偏好和反风格失败信号。
- 对生成图做初步 QA，例如角色是否跑偏、文字是否过密、密度档位是否误判、布局是否重复。

仍然需要：

- 如果要输出真实图片文件，还需要接入生图模型或外部图片生成工具。

### 生图模型

用于把 `visual-style-seed.md`、`ip-subject.md`、`composition-patterns.md`、密度档位和单张 prompt 转成图片。

最低要求：

- 支持文本到图像。
- 支持 16:9 或接近 16:9 的正文配图。
- 能遵守白底、手绘、留白、短中文批注和轻/中/高密度档位等约束。

更好要求：

- 支持参考图输入，用于保持用户上传角色的识别点。
- 支持图像编辑或局部重绘，用于修正文字、角色比例、构图重复和小错误。
- 支持批量或连续生成，用于 3-10 张系列配图。

### 图像编辑模型

适合：

- 保留用户角色，只改动作、道具、场景或画风。
- 删除错误文字。
- 调整局部构图。
- 统一一组图的角色比例和画面密度。

如果没有图像编辑能力，只能重新生成整张图，角色一致性会更不稳定。

## 推荐执行链路

1. 文本/多模态模型读取用户材料。
2. 生成 Style DNA、反风格清单、视觉主体、密度档位和布局计划。
3. 文本/多模态模型把每张图写成明确 scene plan。
4. 生图模型生成图片。
5. 多模态模型或人工检查角色、布局、文字、公开案例避让和反 AI 味。
6. 需要时用图像编辑模型局部修正。

窗口实验日志链路：

1. 读取当前窗口、用户提供的摘要或项目材料。
2. 生成实验卡，过滤不适合公开的信息。
3. 选择 3-5 张叙事节点、密度档位、呈现载体和布局。
4. 有生图能力时生成图片；没有时输出可复制 prompt。

## 当前运行环境

在不同运行环境中，生图能力通常依赖外层图片生成工具或模型。这个能力不属于 `style-avatar-workshop` 文件夹本身。

因此，复制本 Skill 到没有生图工具的环境时，它仍然可以产出个人风格资产和图片 prompt，但不能自己生成图片文件。

## 无生图能力时的用户提示

当用户要求“生成图片”“出图”“画一张”“做配图”，但当前环境没有生图工具或生图模型时，必须先说清楚限制，再给可执行替代物。

推荐话术：

```text
当前模型/环境不能直接生成图片。我可以先按你的文章和角色生成布局方案与可复制的生图 prompt；你可以把 prompt 放到可用的生图工具里生成图片。
```

窗口实验日志推荐话术：

```text
当前模型/环境不能直接生成图片。我可以先把这个窗口整理成实验卡、3-5 张手绘图布局计划和可复制的生图 prompt；有生图工具时再把这些 prompt 生成图片。
```

不要这样说：

- “已生成图片”，但实际只给了 prompt。
- “图片在附件里”，但没有真实图片文件。
- 不说明能力限制，直接输出一组 prompt。

## 写入子 Skill 时

生成个人风格子 Skill 时，如果用户需要配图，应该在 `prompt-template.md` 或 `composition-patterns.md` 里说明：

- 有生图工具时：按布局计划和密度档位生成图片。
- 没有生图工具时：先提示用户当前模型/环境不能直接生成图片，再输出可复制到生图工具的 prompt。
- 有多模态能力时：先读取用户角色图并提取识别点。
- 没有多模态能力时：要求用户用文字描述角色，或只输出待校准假设。
