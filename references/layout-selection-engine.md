# Layout Selection Engine

用于根据用户上传内容自动选择配图布局。不要让用户从布局菜单里手动挑；先判断内容，再给出 1 个最适合的布局。生成连续内容时，先产出布局规划表，再写每张图的 prompt。

## 输入信号

先把用户上传内容整理成这张卡：

```markdown
## Content Card

- 任务：App 介绍 / 教程 / 观点 / 案例 / 品牌故事 / 活动 / 方法论 / UI 说明 / 复盘 / 其他
- 材料：文章 / 网页 / 截图 / 角色图 / 产品图 / 表格 / 聊天记录 / 音频线索 / 多文件
- 核心动作：记录 / 分类 / 对比 / 判断 / 解释 / 保存 / 生成 / 沟通 / 校准 / 发布
- 信息密度：低 / 中 / 高
- 情绪强度：冷静 / 焦虑 / 冲突 / 鼓励 / 复盘
- 是否需要证据感：低 / 中 / 高
- 是否需要角色强参与：低 / 中 / 高
- 输出平台：公众号 / 小红书 / B站 / 官网 / PPT / Notion / 社群 / 通用
- 平台位置：封面 / 正文配图 / 轮播单页 / 长图 / 视频封面 / 分享卡片 / 通用

- 安全区：中心方形 / 顶底 UI 遮挡 / 信息流裁切 / 无 / 待判断
- 画面用途：正文配图 / 解释图 / 课程讲义 / PPT / 无限画布 / 复盘工作台 / 封面
- 推荐密度：轻配图 / 中密度解释图 / 高密度工作台 / 待判断
- 推荐尺度：局部轻描 / 小场景 / 完整场景 / 工作台 / 待判断
- 留白偏好：自动 / 留白多 / 平衡 / 内容更丰富 / 待判断
- 推荐载体：基础载体 / 新颖载体 / 待判断。完整列表见 `presentation-carriers.md`
- 隐喻方式：秒懂型 / 延迟型 / 系统型 / 待判断

- 露出线索：皱纸条一角 / 杯底字迹 / 旧日期标签 / 被贴住红点旁的小纸条 / 其他 / 待判断
```

没有足够信息时，可以先用合理推断，但要标为“待校准假设”。

## 自动选择流程

1. 先判断内容任务，不从布局开始。
2. 抽象出这张图真正要解释的表达任务，例如卡点、复用、筛选、成型、沉淀、建立信任。
3. 判断画面用途、密度档位、构图尺度和留白偏好：正文配图优先轻配图和局部轻描，教程/功能说明优先中密度解释图，复盘/PPT/无限画布/“一张图讲清楚”优先高密度工作台。
4. 如果用户指定平台、封面、轮播、长图、社媒发布或尺寸，读取 `platform-image-sizes.md`，先确定推荐尺寸、比例、安全区和是否需要重排构图。
5. 读取 `presentation-carriers.md`，先选择隐喻方式和日常动作隐喻，再选择遮挡关系、露出线索、呈现载体和视觉隐喻动作；不要默认使用纸、笔、卡片、文件夹、时间线或 UI。
6. 如果密度不确定，默认先给轻配图；当内容明显也适合拆解时，输出 A/B/C 三个密度方案并推荐一个。
7. 过滤掉不适合的布局：例如高严肃度证据内容不要用过度可爱的漫画分镜；超宽公众号头图不要用竖向流程；小红书 3:4 不要套横向三栏。
8. 检查公开案例避让规则；如果候选场景像某个公开案例的物件组合、画面骨架或动作节奏，必须重写。
9. 从布局库中选 2-3 个候选。
10. 用下方规则打分：核心动作匹配 +2，材料形态匹配 +2，平台匹配 +1，尺寸比例匹配 +2，安全区清晰 +1，密度档位匹配 +2，隐喻方式匹配 +2，日常动作隐喻清楚 +2，遮挡/露出关系清楚 +2，载体匹配 +1，粗糙感符合 +1，能让主体参与核心动作 +1，能避免上一张构图 +2，像公开案例 -3，信息超过档位预算 -3，低密度画完整复杂场景 -4，场景过度精致 -3，像道具摆拍或概念图标 -3，连续使用纸笔卡片 -3，直接裁切导致文字/角色出安全区 -4。
11. 选择最高分布局；分数相同，选更少见、更能区别于上一张的布局。
12. 写出选择理由，不超过 2 句。

## 留白偏好控制

默认根据内容自动判断，不要求用户每次选择。但用户明确说“留白多一点”“更精致”“别太满”“内容更丰富”“一张图讲清楚”时，用户偏好优先于默认判断。

| 偏好 | 使用场景 | 规则 |
| --- | --- | --- |
| 自动 | 用户没提密度或留白 | 根据平台、材料复杂度和画面用途自动选择 |
| 留白多 | 用户觉得画面满、不精致、想要正文呼吸感 | 优先轻配图和局部轻描；主体群占画布宽度 25%-38%、高度 20%-32%；四周至少 35% 空白安全边；中文批注 1-3 个；信息多就拆成系列 |
| 平衡 | 用户需要清楚但不想太空 | 轻配图或中密度解释图；主体群占画布宽度 35%-50%；四周至少 25% 空白安全边；中文批注 2-6 个 |
| 内容更丰富 | 用户要解释更多、教程、机制或“一张讲清” | 可升到中密度或高密度；必须有清晰分区和主阅读路径；不能只是把主体放大或把纸片堆满 |

偏好不是画风菜单。它只控制画面承载量、主体缩放和留白安全边。

如果内容自动判断和用户偏好冲突：

- 用户要留白多，但内容很多：先拆成系列图，不把所有信息塞进一张。
- 用户要内容更丰富，但只是正文配图：给 1 张留白版 + 1 张解释版的方案，推荐正文使用留白版。
- 用户要一张讲清楚：允许升为高密度工作台，但必须提前说明会牺牲呼吸感。

## 密度档位选择规则

| 档位 | 默认用途 | 预算 | 推荐布局 |
| --- | --- | --- | --- |
| 轻配图 | 正文配图、小红书、公众号、产品介绍、清爽去 AI 味 | 1 个小局部，1 个清楚生活动作，2-4 个物件，1 个遮挡/露出/处理关系，0-2 个短标注，0-1 条箭头，至少 45%-55% 留白；主体群占画布宽度 30%-45%、高度 25%-40%；四周保留至少 25% 安全边；不能是道具摆拍 | 局部轻描、特写动作、对话现场、反风格拦截、前后对比、极简俯视桌面 |
| 中密度解释图 | 功能说明、教程步骤、案例拆解、单张解释一个机制 | 1 个粗糙小场景 + 1 个动作主线 + 2 个信息区，3-6 个短标注，4-7 个物件，1-2 条连线，至少 35% 留白；最多 2 类主要载体；必须由动作驱动，不是卡片堆叠 | 剖面盒子、控制台、地图路线、资产工具箱、小漫画分镜 |
| 高密度工作台 | 方法论、复盘、课程讲义、PPT、无限画布、一张图讲清楚 | 3 个清晰分区，8-12 个短标注，12-20 个信息承载物，3-6 条连线，至少 15% 留白；必须有主阅读路径；场景仍保持粗糙手绘，不做商业信息图 | 便签墙、图鉴墙、时间轴、实验台、抽屉/收纳柜、楼层剖面 |

高密度必须有清晰分区和主阅读路径；不能只是把材料堆满。

## 密度差异校准

密度差异必须是视觉结构差异，不只是多写几个标签。

- 轻配图：像正文旁边的一张呼吸图。默认使用“局部轻描”：一个小局部 + 一个生活动作关系 + 2-4 个物件，不画完整房间、完整街区、完整餐厅、完整店铺、完整车站、完整工作台或完整系统。主体群缩在画面中间，外圈白边要明显；不要画总览、资料墙、文件夹阵列、多分区面板或单纯道具摆拍。
- 中密度解释图：像单个机制的解释现场。允许粗糙小场景和 2 个信息区，但必须由日常动作驱动；如果已经有三个大文件夹、三列卡片或两组以上纸片，通常过密。
- 高密度工作台：像可以放进 PPT、课程讲义或无限画布的一张工作台。必须有 3 个分区、主阅读路径和视觉层级；如果只是把轻配图旁边堆满纸片，仍然失败。场景可以更完整，但必须粗糙、不精修。
- 做低密度/高密度对比时，缩略图一眼应能看出：低密度是“一个动作”，高密度是“一个系统”。如果只靠文字数量区别，重写布局。

当用户没有指定密度时：

- 输出平台是公众号/小红书/正文：默认轻配图。
- 任务是教程/功能解释/案例拆解：默认中密度解释图。
- 任务是复盘/方法论/PPT/无限画布：默认高密度工作台。
- 内容既可清爽展示又可深入拆解：给 A 轻配图、B 中密度、C 高密度三个方案，推荐一个，不必每次都生三张。

## 隐喻方式自动分流

| 隐喻方式 | 默认触发 | 构图处理 |
| --- | --- | --- |
| 秒懂型 | 教程、功能说明、平台尺寸、用户明确要讲清楚 | 关系直接，动作明确，优先掀、夹、压、抖、贴住等能直接看懂的动作 |
| 延迟型 | 正文配图、个人 IP、观点、社媒内容、用户想要有味道 | 第一眼可以是孤独、有留白、粗糙的小局部，第二眼从遮挡、露出、处理痕迹读出意思 |
| 系统型 | 方法论、复盘、课程讲义、无限画布、一张图讲清楚 | 允许工作台或多区块，但必须有粗糙手绘质感和主阅读路径 |

不确定时：低密度选延迟型，中密度选秒懂型，高密度选系统型。

## 平台尺寸适配

当用户指定小红书、微信公众号、X、Instagram、短视频、PPT、论坛或任何画面尺寸时，先读取 `platform-image-sizes.md`，再决定布局。尺寸不是最后裁切步骤，而是构图输入。

默认规则：

- 小红书图文：优先 1080 x 1440（3:4）或 1080 x 1350（4:5），使用竖向上中下结构。
- 微信公众号头图：优先 900 x 383（2.35:1），关键内容放中心方形安全区，左右两侧只放氛围和轻批注。
- 微信公众号正文配图：优先 900 x 500、1080 x 608 或通用 16:9，适合轻配图和中密度解释图。
- X 信息流：优先 1200 x 675 或 1280 x 720（16:9）；链接卡片用 1200 x 628；方图用 1080 x 1080。
- Instagram / Threads / Facebook Feed：优先 1080 x 1350（4:5）或 1080 x 1080。
- Stories / Reels / 抖音 / TikTok / 视频号：优先 1080 x 1920（9:16），顶部和底部保留 UI 安全区。
- PPT / 视频封面 / 论坛展示：优先 16:9。

一图多平台时：

- 不要把一张 16:9 图直接裁成小红书竖图或公众号头图。
- 优先生成横版、竖版、方版三套同源多版。
- 每个版本都要重新给 `Exact Chinese text allowed`，并重新检查角色脸、文字和核心道具是否在安全区。
- 如果用户只想要一张通用图，默认选 1:1 或 4:5，并说明会牺牲某些平台的最佳展示。

## 构图尺度和留白安全边

构图尺度必须和密度一起判断。不要因为选择了新颖载体，就自动画完整场景。

- **局部轻描**：只画动作发生的一个小局部，例如被子角压住纸条、卡纸下面露出线索、抽屉缝夹着标签、杯底沉着答案、旧相框边露出图角、胶带贴住红点。适合轻配图和正文配图。
- **小场景**：画一个粗糙小范围操作现场，例如桌角、柜台、窗口、半个控制台、空长椅、半个货架、夜晚桌灯下的一角纸面。适合中密度解释图。
- **完整场景**：画房间、街区、路线、后台、展柜等完整空间。只在内容需要环境关系时使用。
- **工作台**：画多区块、多材料和主阅读路径。只用于高密度工作台、PPT、课程讲义、无限画布或“一张图讲清楚”。

轻配图硬约束：

- 主体群不要贴边，不要铺满画布；宽度超过画布 45% 或高度超过 40% 时，先缩小而不是删留白。
- 用户反馈“周围留白太少”“不精致”“太满”时，主体群进一步缩到画布宽度 30%-40%、高度 25%-35%，四周安全边提升到至少 30%。
- 批注必须像小手写注，不要变成标题。红字批注不应是画面最大文字。
- 图片中文字必须来自短词白名单，不允许自动扩写标题、解释句、段落或检查清单。
- 低密度必须写出日常动作隐喻、遮挡关系和露出线索；如果一个小局部不足以讲清，拆成系列或升级中密度，不要直接画完整复杂场景。
- 如果载体是微型街区、暗房、店铺、后台、地铁、剪辑、印刷、影棚、温室、陶艺、录音或总机等新颖载体，轻配图只取局部，不画完整空间。

当内容材料很多时：

- 文章长：选一个最能代表文章的动作，不画完整结构。
- 产品功能多：只画一个功能现场，其他功能拆到系列图。
- 诊断点多：只画最严重的一个漂移点。
- 系列规划多：画“正在挑选/剔除”的动作，不把所有缩略图都画完整。
- 网页截图复杂：只取局部纸片或一个按钮/表单/片段，不临摹整页。
- 纸片、卡片、文件夹已经连续出现：下一张改用日历、地图、仪表盘、对话现场、空间剖面、手部特写或真实道具，不继续堆纸。

## 呈现载体选择

完整载体库见 `presentation-carriers.md`。这里保留高频选择规则：

- 评论、追问、用户反馈：优先对话现场、时间记录、样本图鉴、操作面板；不要每次都画评论纸片。
- 产品功能和 App 介绍：优先操作面板、空间剖面、特写动作、路线地图；不要默认画文件夹和卡片。
- 教程步骤：优先路线地图、小漫画分镜、操作面板、时间记录；不要只画横向箭头。
- 风格校准和去 AI 味：优先实验检测、工具修理、纸面文具、样本图鉴；不要每次都只用红笔批改。
- 复盘和方法论：优先时间记录、样本图鉴、空间剖面、操作面板；不要只用便签墙。
- 证据和合规：优先票据档案、时间记录、俯视桌面、特写动作。
- 发布和展示：优先舞台展示、路线地图、对话现场。
- 用户反馈“不够新颖”：优先从 `presentation-carriers.md` 的日常动作隐喻表里选 3 个动作候选，例如掀、夹、压、揉、撕、抖、晾、补、泡、沉、捞、贴住，再搭配暗房显影、收音调频、地铁换乘、微型街区、裁缝试衣、沙盘推演、小店货架、舞台后台、印刷拼版、录音剪辑台或镜片校准等载体推荐 1 个。

如果内容没有明显载体，默认从“真实材料”里抽取：评论就用对话，步骤就用路线，功能就用开关，复盘就用时间，分类就用图鉴，修复就用工具。

载体选择必须同时写出隐喻方式、日常动作隐喻、遮挡关系、露出线索和视觉隐喻动作，例如：`延迟型 / 从被子下面摸出皱纸条 / 被子盖住线索 / 纸条露出一角 = 从混乱材料里找到真正有用的信息`。如果只能写出场景名或道具名，说明载体没有选好。

## 布局库

| 布局 | 最适合内容 | 主体动作 | 避免 |
| --- | --- | --- | --- |
| 输入到输出 | 把混乱材料变成结果 | 搬运、压平、吐出、整理 | 连续多张使用 |
| 前后对比 | before/after、默认 AI vs 像用户 | 推开、擦掉、替换 | 两侧信息太满 |
| 反风格拦截 | 禁用词、审核、拒绝错误方向 | 挡住、盖章、圈出 | 满屏红字 |
| 资产工具箱 | 模块、资源包、组件化能力 | 打开、分格、收纳 | 文件树截图 |
| 小漫画分镜 | 行为变化、用户旅程、故事感 | 每格一个动作 | 做成教程 PPT |
| 俯视桌面 | 文书、证据、清单、整理 | 只露手或半身在整理 | 横向流程排布 |
| 剖面盒子 | 系统内部、云同步、工具机制 | 在盒内搬卡、修部件 | 复杂架构图 |
| 地图路线 | 多步骤路径、成长、流程 | 沿路线移动、贴路标 | 直线箭头串卡 |
| 特写动作 | 按按钮、盖章、锁住、圈重点 | 局部手势和道具 | 讲太多步骤 |
| 图鉴墙 | 分类、收藏、案例库、IP 角色库 | 钉卡、贴标签、看图鉴 | 整齐网格太死 |
| 楼层剖面 | 空间关系、上下游、邻里、因果传导 | 在楼层间追踪路径 | 透视复杂到看不懂 |
| 时间轴 | 长期记录、复盘、版本演化 | 贴日期、标异常 | 时间点太多 |
| 日历热力图 | 频率、周期、习惯、连续打卡 | 圈日期、贴标记 | 数据过密 |
| 放大镜局部 | 识别、诊断、细节分析 | 放大、框选、标注 | 只画放大镜装饰 |
| 对话现场 | 沟通、协商、用户反馈、客服 | 递材料、解释、记录 | 变成吵架画面 |
| 档案袋 | 证据、资料归档、授权材料 | 装袋、封口、编号 | 像官方公文模板 |
| 控制台 | 参数、策略、模式切换 | 调旋钮、按按钮 | 武器化、攻击化 |
| 实验台 | 测试、校准、A/B、调参 | 滴管、量杯、测试卡 | 科幻实验室 |
| 舞台聚光 | 发布、展示、主角介绍 | 拉幕、举牌、站台 | 营销海报感 |
| 拼图/积木 | 组合、搭建、模块关系 | 拼接、支撑、替换 | 过度儿童化 |
| 天平/秤盘 | 判断、取舍、权衡利弊 | 加砝码、调平衡 | 法律审判感 |
| 电路/管线 | 依赖、自动化、数据流 | 接线、插头、排障 | 复杂技术图 |
| 抽屉/收纳柜 | 分类、知识库、历史记录 | 拉抽屉、归档 | 每格都写满字 |
| 便签墙 | 头脑风暴、选题、评论整理 | 移动便签、分组 | 纯便利贴模板 |
| 角色换装台 | 用户上传角色、IP 变体、风格切换 | 换道具、换外套、校准比例 | 改掉核心识别点 |

## 内容到布局的默认映射

- App 是干什么的：输入到输出、剖面盒子、地图路线。
- 功能介绍：控制台、资产工具箱、剖面盒子、特写动作。
- 教程步骤：地图路线、小漫画分镜、时间轴。
- 用户痛点：前后对比、对话现场、楼层剖面。
- 证据/合规：档案袋、俯视桌面、天平/秤盘、特写动作。
- 分类/图鉴：图鉴墙、便签墙、抽屉/收纳柜。
- 长期记录：时间轴、日历热力图、云朵/剖面盒子。
- AI 识别/诊断：放大镜局部、实验台、电路/管线。
- 角色设定：角色换装台、舞台聚光、图鉴墙。
- 观点批改：反风格拦截、红笔批改、俯视桌面。

## 公开案例避让

这些不是布局菜单，而是生成前的原创性检查。遇到常见抽象主题时，保留“要解释的意思”，但不要沿用任何公开案例的具体物件、物件组合、主体动作或画面节奏。

先用三问重构画面：

1. 这个内容自己的材料是什么：网页、截图、按钮、表单、文档、评论、订单、证据、日历、地图、人物对话或实物场景？
2. 主体能做哪个真实动作：圈出、封存、对照、排序、递交、标记、校准、开关、拆分、归档、复盘？
3. 这个动作更适合什么视角：俯视桌面、局部特写、剖面空间、对话现场、档案收纳、时间记录、控制台或分镜？

| 表达任务 | 避让原则 | 重构方向 |
| --- | --- | --- |
| 流程卡点 | 不套用现成直线流程画面 | 从用户材料里找“卡住的状态”，用现场排障、状态标记、路径切换或局部特写表达 |
| 素材复用 | 不用动物、食物或切分物件表达复用 | 用版本、母版、组件、场景变体、文件副本或平台适配表达 |
| 信息筛选 | 不用打捞式深度隐喻表达筛选 | 用索引、筛选、标注、分层查看、证据整理或搜索结果表达 |
| 想法成型 | 不用机械挤压表达想法变方案 | 用草稿校准、参数调试、候选方案对照、便签收束或版本选择表达 |
| 经验沉淀 | 不用容器发酵表达长期积累 | 用时间记录、版本档案、周期复盘、历史轨迹或样本对比表达 |
| 信任建立 | 不用两端连接的通用隐喻表达信任 | 用对话现场、证据递交、权限确认、结果回访或关系渐进表达 |

如果用户明确上传了某个物件或要求使用某个物件，可以使用，但必须来自用户材料，并改变视角、信息承载物和主体动作，不能复用公开案例的画面骨架。

## 系列规划

连续 3 张以上时，必须先给布局表：

```markdown
| 序号 | 主题 | 内容信号 | 选择布局 | 避重理由 | 主体动作 |
| --- | --- | --- | --- | --- | --- |
```

规则：

- 相邻两张不能使用同一布局。
- 5 张以内至少使用 3 种布局。
- 10 张以内至少使用 6 种布局。
- 同一布局家族最多连续出现 1 次；流程类、桌面类、墙面类、控制台类、特写类要轮换。
- 不要让每张都是“主体站中间 + 旁边几张卡片”。
- 相邻两张不能使用同一类主要信息承载物。纸片、卡片、便签、文件夹属于同一类；日历/时间轴、控制台/仪表、地图/路径、对话气泡、空间剖面、真实道具各算不同类。
- 5 张以内最多 2 张以纸片/卡片/文件夹为主要承载物；如果第二张和第三张都靠纸片承载信息，必须重写其中一张。
- 3 张以内至少使用 3 类呈现载体；5 张以内至少使用 4 类呈现载体；10 张以内至少使用 6 类呈现载体。
- 如果用户上传了角色图，至少 30% 的图使用非全身构图：半身、手部特写、俯视露角、背影或侧面，避免角色每张都站在画面中央。

## 布局家族

- 流程类：输入到输出、地图路线、时间轴、日历热力图。
- 对比类：前后对比、反风格拦截、天平/秤盘。
- 整理类：俯视桌面、档案袋、抽屉/收纳柜、便签墙。
- 空间类：剖面盒子、楼层剖面、舞台聚光。
- 观察类：放大镜局部、实验台、图鉴墙。
- 操作类：特写动作、控制台、电路/管线、拼图/积木、角色换装台。
- 对话类：对话现场、小漫画分镜。
